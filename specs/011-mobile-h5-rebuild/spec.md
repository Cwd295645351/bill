# Feature Specification: 移动端 H5 重建

**Feature Branch**: `011-mobile-h5-rebuild`

**Created**: 2026-10-28

**Status**: Draft

**Input**: User description: "重新开发一套移动端 H5，功能对齐微信小程序（账本 / 记一笔 / 我的，以及账单详情、记/改账、搜索、加入账本）；登录与 PC 一致（账号密码）；宪章 v3.0.0 允许新建 mobile-h5、部署 /mobile/，旧 /mobile/ 永久关停；禁止修改 specs/001–010；本阶段只写规格，不写实现。"

## Background & Decision

产品曾关停旧手机浏览器记账入口（`/mobile/`）。宪章已升至 **v3.0.0**：永久关停旧入口，同时允许**新建**独立移动端 H5，服务路径为 `/mobile/`。本规格只定义该新产品能力与验收边界，**禁止修改**已归档 `specs/001`–`010`（含 `005-remove-mobile-web`）。

能力范围以现有微信小程序为参照：主入口为「账本 / 记一笔 / 我的」，并覆盖账单详情、记账、改账、搜索、加入账本。登录方式与电脑端一致：账号 + 密码。小程序专属的微信绑定/静默登录不自动照搬到 H5：首期仅提供账号密码登录（无注册入口）；不提供微信绑定相关页面。

本阶段产出规格与质量清单；**不写业务代码**。技术目录与实现栈细节在后续 `/speckit-plan` 落定（须符合宪章：新建 `mobile-h5/`、部署 `/mobile/`、复用现有统一 API，不恢复旧 `mobile/`）。


## Clarifications

### Session 2026-10-28

- Q: H5 首期是否提供与 PC 对等的注册入口？ → A: 仅登录；不提供 H5 注册（新用户须先在电脑端或其他已有渠道注册）。
- Q: H5 首期是否保留微信账号绑定相关页面？ → A: 直接去掉「绑定」类流程；首期不依赖微信即可完成账号密码登录与记账主路径。
## User Scenarios & Testing *(mandatory)*

目标用户：已有家庭账本账号、需要在手机浏览器（含微信内置浏览器与独立浏览器）完成日常记账的人。电脑端网页与微信小程序继续各自服务；本特性只交付新 H5。

### User Story 1 - 账号密码登录进入 H5 (Priority: P1)

用户在手机浏览器打开新移动端入口，使用与电脑端相同的账号和密码登录。登录成功后进入主界面；凭证失效或未登录时只能看到登录相关页面，无法查看账本与账单。

**Why this priority**: 没有可用登录就无法使用任何记账能力；且产品已锁定与 PC 一致的账号密码方式。

**Independent Test**: 用已知正确账号密码在手机浏览器完成登录并进入主界面；用错误密码看到明确失败提示且不进入业务页。

**Acceptance Scenarios**:

1. **Given** 用户持有有效账号密码，**When** 在新移动端入口提交登录，**Then** 进入主界面并可看到自己有权限的账本相关内容。
2. **Given** 用户输入错误密码或未知账号，**When** 提交登录，**Then** 停留在登录流程并看到可读的失败说明，不暴露内部错误细节。
3. **Given** 用户此前已登录且凭证仍有效，**When** 再次打开入口，**Then** 无需重复输入密码即可进入主界面（或按产品既有会话规则自动续期）。
4. **Given** 用户凭证已失效，**When** 访问需登录的页面，**Then** 被引导回登录，且不会看到他人或过期会话下的账本数据。

---

### User Story 2 - 浏览账本并进入账单 (Priority: P1)

登录后，用户在「账本」入口看到自己可访问的账本列表，点进某一账本后进入账单详情视图。**账本列表与账单详情的交互与信息架构须与微信小程序对等**（产品确认：和小程序完全一致），包括：列表可新建账本、可左滑删除本人创建的账本；详情顶栏六项汇总、按日分组与当日收支合计、归属人·分类行展示、本人左滑删除流水、右下角记一笔 FAB、查看照片、创建者邀请成员（H5 以展示/复制邀请码代替微信分享）。

**Why this priority**: 「账本」是小程序三个主入口之一，也是进入记账上下文的必经路径。

**Independent Test**: 登录后仅验证账本列表与进入某一账本详情，不依赖改账或搜索即可演示价值。

**Acceptance Scenarios**:

1. **Given** 用户至少属于一个账本，**When** 打开「账本」，**Then** 看到自己有权限的账本列表（不含无权账本）；行展示以账本名为主，对齐小程序。
2. **Given** 用户点击某一账本，**When** 进入账单详情，**Then** 看到与小程序对等的汇总（年度支出、当月支出、剩余预算、总投资、总消费、总收入）、支出/收入切换流水、按日分组（含当日收支合计）、记一笔入口与搜索入口。
3. **Given** 用户当前不属于任何账本，**When** 打开「账本」，**Then** 看到空状态「还没有账本，创建一个或让家人邀请你」，而不是报错白屏。
4. **Given** 用户在账本列表，**When** 新建账本（名称 3–10 位中文/字母/数字）或左滑删除本人创建的账本并确认，**Then** 分别调用现网 createBill / deleteBill 语义接口并刷新列表。
5. **Given** 用户在账单详情查看本人流水，**When** 左滑删除并确认，**Then** 该笔删除成功；非本人流水不可删除/编辑。
6. **Given** 用户是账本创建者，**When** 点击邀请成员，**Then** H5 展示邀请码并支持复制（不要求微信分享能力）。

---

### User Story 3 - 记一笔 (Priority: P1)

用户通过「记一笔」或从账本上下文进入记账流程，选择类型、金额、归属与必要字段后保存。保存成功后能在账单中看到该笔记录。规则与现有产品一致：支出可按成员分摊；收入仅归属一名成员；仅记录创建者可编辑/删除自己的明细（与用户手册「权限」一致）。

**Why this priority**: 日常记账是移动端核心价值；没有记一笔则 H5 重建无意义。

**Independent Test**: 在已登录且有账本的前提下完成一笔支出保存，并在账单中确认出现。

**Acceptance Scenarios**:

1. **Given** 用户已进入某账本上下文，**When** 完成必填项并保存一笔支出，**Then** 保存成功且该笔出现在对应账单中。
2. **Given** 用户记一笔收入，**When** 选择归属，**Then** 只能归属一名成员（不可多选或「全部」）。
3. **Given** 必填项缺失或金额非法，**When** 尝试保存，**Then** 阻止保存并提示需补全或修正的内容。
4. **Given** 用户不是某笔记录的创建者，**When** 尝试编辑或删除该笔，**Then** 操作被拒绝（与现有权限规则一致）。

---

### User Story 4 - 搜索、查看与修改自己的记录 (Priority: P2)

用户可搜索账本内记录，打开单笔详情，并在权限允许时修改自己创建的记录。

**Why this priority**: 纠错与查找是记账闭环的一部分，但可在「能登录 + 能记一笔」之后交付。

**Independent Test**: 对已知关键字搜索出目标记录，并成功改自己创建的一笔金额或备注类字段。

**Acceptance Scenarios**:

1. **Given** 账本内存在可匹配关键字的记录，**When** 用户搜索，**Then** 结果列表包含这些记录且不含明显无关项（以现有小程序搜索行为为参照）。
2. **Given** 用户是某笔记录的创建者，**When** 编辑并保存，**Then** 账单中展示更新后的内容。
3. **Given** 搜索无匹配，**When** 查看结果，**Then** 看到空状态而非错误页。

---

### User Story 5 - 「我的」与退出 (Priority: P2)

用户在「我的」查看当前登录身份相关信息，并能退出登录。退出后再次访问业务页需重新登录。

**Why this priority**: 身份确认与安全退出是多设备使用的基本能力。

**Independent Test**: 打开「我的」确认展示当前用户信息，执行退出后无法再直接进入账本页。

**Acceptance Scenarios**:

1. **Given** 用户已登录，**When** 打开「我的」，**Then** 能识别当前账号身份（如昵称/账号展示，以现有小程序「我的」信息密度为参照）；不提供微信绑定入口或微信头像体系。
2. **Given** 用户选择退出，**When** 确认退出，**Then** 本地会话清除，再进业务入口需重新登录。

---

### User Story 6 - 通过邀请加入账本 (Priority: P3)

用户持有加入账本的邀请链接或口令（与现有产品加入流程对等），在已登录状态下完成加入，之后在「账本」列表中看到新账本。

**Why this priority**: 家庭成员扩展依赖此能力，但可在核心记账可用后再接。

**Independent Test**: 用有效邀请在测试账号上加入账本，列表出现该账本；无效邀请有明确失败提示。

**Acceptance Scenarios**:

1. **Given** 用户已登录且邀请有效，**When** 完成加入流程，**Then** 成为该账本成员并在列表中可见。
2. **Given** 邀请无效或已过期，**When** 尝试加入，**Then** 看到失败说明且不产生错误成员关系。
3. **Given** 用户未登录，**When** 打开加入入口，**Then** 先完成登录再继续加入（或明确提示需先登录）。

---

### Edge Cases

- 弱网或请求失败时：保存记账、加载账本列表须有可读失败提示，允许重试，不静默丢数据。
- 同一账号在电脑端修改了账本或记录后，H5 再次进入对应页应看到最新数据（以常规刷新/重进为准，不要求实时推送）。
- 用户只有查看权、没有记账权时（若产品角色如此区分）：隐藏或禁用记账入口，并说明原因。
- 旧书签或外链仍指向 `/mobile/`：继续保持关停行为（与宪章一致），不自动跳进新 H5 业务页，除非后续单独产品决定做说明页（本规格不要求恢复旧站）。
- 横竖屏与常见手机宽度下主流程可完成；不要求平板专属布局。



### 产品澄清（相对初稿，仍属 011）

- 用户确认 H5「和小程序完全一致」，**允许并要求** H5 新建/删除账本；账单详情汇总与行展示、左滑删除、FAB、照片预览、邀请码等对齐小程序。本澄清仍落在 `011-mobile-h5-rebuild`，**不开 012**。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供独立于电脑端网页、独立于微信小程序的新移动端 Web 入口，供手机浏览器完成登录与日常记账。
- **FR-002**: 系统 MUST 使用与电脑端相同的账号 + 密码方式认证移动端用户；认证成功后的访问凭证与现有统一接口体系兼容，使同一账号在电脑端与 H5 看到同一账本与记录权限。
- **FR-003**: 系统 MUST 提供与小程序对等的三个主入口：「账本」「记一笔」「我的」。
- **FR-004**: 系统 MUST 支持账本列表、新建/删除本人创建的账本、进入单一账本的账单详情（汇总与流水展示对齐小程序）、新建记录、编辑/删除自己的记录、按关键字搜索记录；创建者可获取邀请码供他人加入。
- **FR-005**: 系统 MUST 支持在已登录前提下通过既有邀请机制加入账本。
- **FR-006**: 记账与权限规则 MUST 与现行产品一致（含：仅创建者改删自己的明细；支出分摊与收入单成员归属等，以用户手册为准）。
- **FR-007**: 未登录用户 MUST 无法读取账本列表、账单明细或提交记账；会话失效时 MUST 回到可登录状态。
- **FR-008**: 新移动端 MUST 复用现有统一业务接口能力，不得为 H5 另造第二套账本/记账业务语义；允许仅增加入口与展示层所必需的适配，但账本、记录、成员含义须与现网一致。
- **FR-009**: 旧手机站路径 `/mobile/` MUST 保持永久关停；本特性 MUST NOT 恢复、重挂或把新功能写回旧 `mobile/` 目录。
- **FR-010**: 本特性目录与交付物 MUST 落在新规格目录 `specs/011-mobile-h5-rebuild/`；MUST NOT 修改 `specs/001`–`010` 已归档正文。
- **FR-011**: 新移动端 MUST 仅提供登录，MUST NOT 提供注册入口；尚无账号的用户须先在电脑端或其他已有渠道完成注册后再使用 H5 登录。
- **FR-012**: 新移动端 MUST NOT 提供微信账号绑定、网页授权或类似「绑定」类页面与流程；首期 MUST 仅依赖账号密码登录完成记账主路径，不依赖微信环境。

### Key Entities

- **用户账号**: 与电脑端同一套登录身份；持有密码凭证；在 H5 与 PC 间共享账本成员关系。
- **账本**: 家庭或个人记账容器；用户可属于零个或多个账本。
- **账单记录**: 单笔收支；含金额、类型、归属/分摊、创建者、时间等；权限绑在创建者上。
- **邀请**: 用于让已登录用户加入既有账本的凭证或链接。
- **会话**: 登录成功后的访问状态；失效后须重新认证。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 持有有效账号的用户可在 2 分钟内于手机浏览器完成登录并看到自己的账本列表（常规网络）。
- **SC-002**: 用户可在 3 分钟内完成「打开账本 → 记一笔支出 → 在账单中确认出现」的主路径（常规网络、字段齐全）。
- **SC-003**: 同一账号在 H5 与电脑端对同一账本的记录条数与权限表现一致（抽样对比不少于 3 个账本/用户场景，无权限越权）。
- **SC-004**: 未登录或会话失效时，抽测业务深链均无法看到他人账本数据，并被引导至登录。
- **SC-005**: 旧 `/mobile/` 关停行为在本特性交付后仍然成立（不出现旧站记账页复活）。
- **SC-006**: 规格与实现过程中不对 `specs/001`–`010` 产生内容修改。

## Assumptions

- 首期功能对齐小程序现有页面集合（账本、记一笔、我的、账单详情、记账/改账、搜索、加入）；账本列表/详情交互与小程序完全一致（含新建/删除账本）。不在首期把电脑端专属的资产、预算编辑、计划、总览增强、AI 等整页能力搬进 H5（详情顶栏可读汇总所用的预算/余额只读接口除外），除非后续另开规格。
- 登录已锁定为账号密码；首期不提供 H5 注册；不提供微信绑定/网页授权登录。
- 数据与业务规则全部来自现有后端与用户手册；H5 不引入第二套分摊/权限语义。
- 部署上新入口使用 `/mobile/`，工程上使用宪章允许的新建 `mobile-h5/`；具体框架与组件库在 `/speckit-plan` 写明（产品意向：Vue 3 + Vite + TypeScript + Vant，与现网前端技术族一致）。
- 本 `/speckit-specify` 调用只交付规格与清单，不改业务代码、不发版。

## Out of Scope

- 修改或恢复旧 `mobile/`、`/mobile/` 记账站。
- 修改已归档 `specs/001`–`010`。
- 微信小程序本身的功能增删。
- 电脑端 PC 页面改版。
- 首期交付资产趋势、养老计划、预算、AI 记账等 PC 侧重能力（除非后续新规格明确纳入）。
- H5 内注册账号；微信绑定 / 网页授权登录相关页面与流程。
- 本阶段的编码实现、联调与上线操作。
