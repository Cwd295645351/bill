# Feature Specification: 资产成员改名与盘点金额可为零

**Feature Branch**: `008-member-rename-zero-amount`

**Created**: 2026-10-19

**Status**: Draft

**Input**: User description: "家庭资产成员名称需要支持修改，盘点资产时金额允许为0"

## User Scenarios & Testing *(mandatory)*

这次只调整电脑网页上、当前账本里的两件事：已有资产成员的名字可以改；盘点时金额可以记成 0。家庭资产的其余用法保持不变。微信小程序仍然没有资产管理。记账、概览、预算、计划保持原样。

### User Story 1 - 修改资产成员的名字 (Priority: P1)

在当前账本的资产成员名单里，用户可以修改一名尚未隐藏的成员的名字。改完后，名单、成员筛选，以及仍展示该成员的资产，都使用新名字。名下资产的金额、盘点、分类和归属关系不变。

**Why this priority**: 家人的称呼会变。名字不能改时，只能隐藏后重建，历史资产上的称呼就会和现在对不上。

**Independent Test**: 选一名名下已有资产的成员，把名字改成另一个非空名字。名单和这些资产上的名字变为新名字，金额与改名前相同。

**Acceptance Scenarios**:

1. **Given** 当前账本里有一名尚未隐藏的资产成员，**When** 在资产成员名单中把名字改成另一个非空名字并确认，**Then** 名单立即显示新名字。
2. **Given** 这名成员名下已有资产，**When** 改名成功，**Then** 总览、四笔钱、构成里仍展示该成员的位置都显示新名字，每笔资产的金额、分类和盘点与改名前相同。
3. **Given** 成员筛选里能选到这名成员，**When** 改名成功后再打开筛选，**Then** 筛选项使用新名字，选中后仍只看到这名成员的资产。
4. **Given** 用户把名字清空，或只输入空格，**When** 确认，**Then** 修改不生效，名单仍是原名字，并说明名称不能为空。
5. **Given** 去掉首尾空格后的名字超过 64 个字，**When** 确认，**Then** 修改不生效，名单仍是原名字，并说明不能超过 64 个字。
6. **Given** 去掉首尾空格后的名字与原来相同，**When** 确认，**Then** 名字保持不变，不出现失败提示。
7. **Given** 同一账本里已经有另一个同名成员，**When** 把当前这名成员改成同一个名字，**Then** 改名成功，两名成员都在，已有资产仍属于原来的那一名。
8. **Given** 修改没有成功，**When** 再查看该成员和他名下资产，**Then** 名字和金额都与修改前相同。

---

### User Story 2 - 盘点金额可以记成 0 (Priority: P1)

对已有资产新记一笔盘点，或修改已有的一条盘点时，金额可以是 0。0 表示这笔资产在该日期的价值是 0，资产本身还在。空白、不是数字、小于 0 的金额仍然不能保存。

**Why this priority**: 存款用完、理财清仓或一项资产暂时不值钱时，需要把这一天的金额记成 0。现在只能删掉整笔资产，历史就被抹掉了。

**Independent Test**: 打开一笔已有资产，新记一笔金额为 0、日期已填的盘点，保存成功且历史中能看到 0。再把另一条已有盘点的金额改成 0，这一条变为 0，盘点条数不增加。

**Acceptance Scenarios**:

1. **Given** 一笔已有资产，**When** 新记一笔金额为 0 且填写了日期的盘点，**Then** 保存成功，历史中多出这一条，金额显示为 0。
2. **Given** 这条金额为 0 的盘点日期最新，**When** 回到资产列表，**Then** 该资产仍在列表中，当前金额为 0，最近更新日期为这一条的日期。
3. **Given** 一条已有盘点，**When** 只把金额改成 0 并保存，**Then** 这一条显示为 0，盘点条数不变。
4. **Given** 金额为 0 的盘点不是日期最新的一条，**When** 保存，**Then** 这一条显示为 0，当前金额仍是日期最新那条的金额。
5. **Given** 正在编辑一笔已有资产，且当前金额与页面上的金额不同，**When** 把当前金额改成 0 并保存，**Then** 保存成功，并新增一条金额为 0 的盘点；当前金额变为 0。
6. **Given** 一笔资产的当前金额已经是 0，**When** 只修改名称、成员、分类或保险信息后保存，**Then** 保存成功，盘点条数不变，当前金额仍是 0。
7. **Given** 新记盘点、修改盘点或编辑资产的当前金额，**When** 金额留空、不是数字或小于 0，**Then** 不写入，并说明需要填写不小于 0 的数字；已有记录不变。
8. **Given** 用户要新登记一笔资产，**When** 当前金额填写 0、留空、不是数字或小于 0，**Then** 登记失败并说明原因，不产生资产，也不产生盘点。
9. **Given** 一笔资产只剩一条金额为 0 的盘点，**When** 查看操作，**Then** 不能删除这一条，可以把它改成其他不小于 0 的金额。

---

### User Story 3 - 记成 0 之后，合计和历史仍按这笔数计算 (Priority: P2)

金额记成 0 以后，它是一条真实盘点，要参加家庭合计和历史回看。没有盘过点的月份仍然空着，不能因为这次允许填 0，就把没数据的月份画成 0。

**Why this priority**: 0 如果被当成「没有这笔资产」或「这个月没数据」，净资产和月历会对不上。

**Independent Test**: 一笔非负债资产最新盘点为 0。家庭总资产等于其余非负债之和，这笔仍出现在列表里且金额为 0。再看月历：有 0 盘点的月份显示 0，相邻一个没有任何盘点的月份不显示成 0。

**Acceptance Scenarios**:

1. **Given** 一笔非负债资产的当前金额为 0，其余资产不变，**When** 查看家庭合计，**Then** 总资产等于其他非负债之和，这笔以 0 计入；总负债和净资产按同一口径重算。
2. **Given** 一笔负债的当前金额为 0，**When** 查看家庭合计，**Then** 这笔以 0 计入总负债，总资产不变。
3. **Given** 某月月底之前最近一次盘点的金额是 0，**When** 查看月历该月，**Then** 该月金额为 0。
4. **Given** 某月在月底之前没有任何盘点，**When** 查看月历和资产趋势，**Then** 该月仍为空，不显示成 0。
5. **Given** 一笔资产上一次金额大于 0、当前金额为 0，**When** 查看变化，**Then** 能看到减少的金额，变化率为下降 100%。
6. **Given** 上一次金额为 0，**When** 查看变化，**Then** 能看到变化额；不给出变化率。
7. **Given** 构成里某一笔或某一类的金额为 0，**When** 查看构成，**Then** 不出现对应连线；金额为 0 的资产仍留在资产列表中。

---

### Edge Cases

- 名字首尾有空格：去掉空格后再判断空、长度和是否与原名相同。
- 同一账本里可以有相同名字。改成一个已存在的名字仍然成功，资产仍指向原来的那一名成员。
- 已隐藏的成员不在名单里，不能改名，也不会因此重新出现。先改名再隐藏的，名下资产显示最后一次改成的名字。
- 隐藏成员、删除资产、只剩一条盘点不能删除：规则与现在相同。金额为 0 的最后一条可以修改，不能删除。
- 金额写成 0、0.0 或仅含 0 的数字：都视为 0，可以保存。
- 金额为负数、空白或不是数字：盘点和登记都不保存。
- 新登记资产的当前金额为 0：登记失败，不产生资产和盘点。
- 打开修改后不保存就离开：原名字、原盘点金额和日期都不变。
- 同一天已有盘点，再记一笔 0：仍按「同一天取最后保存的那一条」决定当天金额。
- 当前金额为 0 的资产仍出现在列表中。构成图不为 0 金额画连线。
- 没有盘点的月份不补成 0。已经记下 0 的月份按 0 展示。
- 上一次金额为 0：给出变化额，不给出变化率。
- 没有进入账本，或当前用户不是这个账本的成员：不能改这里的成员名，也不能记盘点。
- 其他账本的成员、资产和盘点不受影响。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 当前账本的成员必须能在电脑网页的资产成员名单中，修改一名尚未隐藏的资产成员的名字。
- **FR-002**: 确认改名时，系统必须去掉名字首尾空格。结果为空时必须拒绝，并说明名称不能为空，原名字保持不变。结果超过 64 个字时必须拒绝，并说明不能超过 64 个字，原名字保持不变。
- **FR-003**: 去掉首尾空格后与原名字相同的，必须保持原名字，且不得提示修改失败。
- **FR-004**: 改名成功后，成员名单、成员筛选，以及总览、四笔钱、构成中仍展示该成员的位置，都必须使用新名字。该成员名下资产的金额、盘点、分类和归属关系必须保持不变。
- **FR-005**: 同一账本允许重名。改成已有名字后，资产仍属于原来的那一名成员。
- **FR-006**: 改名未成功，或用户未确认就离开时，原名字必须保持不变。
- **FR-007**: 已隐藏的资产成员不得通过改名重新出现在名单中。隐藏成员不删除其资产的规则必须保持不变。
- **FR-008**: 对已有资产新记盘点，以及修改已有盘点的金额时，金额必须允许为 0。0 表示该日期的价值为 0，资产及其历史盘点必须保留。
- **FR-009**: 编辑已有资产时，当前金额必须允许改为 0。金额因此发生变化时，必须新增一条金额为 0 的盘点。当前金额已经是 0 且本次未改金额时，保存名称、成员、分类或保险信息必须成功，且不得新增盘点。
- **FR-010**: 新记盘点、修改盘点、编辑已有资产的当前金额，以及新登记资产时，空白、不是数字或小于 0 的金额必须拒绝，并说明原因，且不得写入。
- **FR-011**: 新登记资产时，当前金额必须仍大于 0。填写 0 时登记必须失败，不得产生资产或盘点。
- **FR-012**: 日期最新的未删除盘点金额为 0 时，该资产的当前金额必须为 0，并继续出现在资产列表中。家庭总资产、总负债和净资产必须把这个 0 计入对应一侧。
- **FR-013**: 月历和资产趋势中，月底前最近一次盘点金额为 0 的月份必须显示为 0。没有任何盘点的月份必须仍为空，不得显示成 0。
- **FR-014**: 上一次金额大于 0 且当前金额为 0 时，必须给出减少额，变化率为下降 100%。上一次金额为 0 时，必须给出变化额，不得给出变化率。
- **FR-015**: 构成中金额为 0 的连线必须仍然不出现。金额为 0 的资产必须仍留在资产列表中。
- **FR-016**: 只剩一条盘点时仍然不能删除，包括这条金额为 0 的情况。有多条时删除其中一条后，当前金额仍按剩下记录里日期最新的一条计算；该条为 0 时当前金额为 0。
- **FR-017**: 用户只能修改自己所属的当前账本中的资产成员和盘点。其他账本的成员、资产和盘点必须不受影响。
- **FR-018**: 微信小程序不得因此新增资产管理。记账成员名单、记账、概览、预算、计划的现有行为必须保持不变。
- **FR-019**: 用户手册必须写明：资产成员可以改名，改完后相关展示使用新名字，金额不变；盘点金额可以为 0，不能为负数、不能空着、也不能填成不是数字；新登记资产的当前金额仍必须大于 0；金额为 0 的资产还在，要去掉整笔资产仍使用删除。手册中「盘点金额必须大于 0」和「盘点金额必须为正数」必须改成上述说法。

### Key Entities

- **资产成员**：某个账本下只有名字的人。尚未隐藏时可以改名。改名只更换展示用的名字，不改变名下资产。
- **资产**：账本中的一笔钱或一项负债。当前金额来自日期最新的未删除盘点，因此可以为 0。新登记时的当前金额仍须大于 0。
- **盘点**：某一笔资产在某个日期记下的金额。金额可以为 0，不能小于 0，也不能空着。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 任选至少 2 名名下已有资产的成员完成改名。保存后，名单、筛选和这些资产上的名字全部变为新名字；抽查金额与改名前相差为 0。
- **SC-002**: 对至少 1 笔资产新记金额为 0 的盘点，一次保存成功，历史中能看到 0。该条为日期最新时，列表当前金额为 0，家庭净资产与把该笔按 0 手工计入的结果一致。
- **SC-003**: 把至少 1 条已有盘点的金额改成 0 后，该条显示为 0，盘点条数与修改前相同。
- **SC-004**: 金额为负数、空白、不是数字各尝试至少 1 次，都不产生新盘点，原记录保持不变。新登记资产时填写 0，不产生资产。
- **SC-005**: 在至少 1 个同时含「盘点金额为 0 的月份」和「没有任何盘点的月份」的账本中，前者显示 0，后者为空。
- **SC-006**: 熟悉资产页的成员可以在 1 分钟内改完一个成员名字，或为已有资产记下一条金额为 0 的盘点。
- **SC-007**: 打开用户手册的家庭资产说明，能读到成员可以改名，以及盘点金额可以为 0、新登记资产的当前金额仍须大于 0。

## Assumptions

- 本次只改电脑网页上已有的家庭资产。微信小程序不增加资产入口，已退出的手机网页不恢复。
- 资产成员和记账成员仍是两份名单。本次只让资产成员的名字可以修改，不改记账成员的规则。
- 名字长度继续沿用现有上限：去掉首尾空格后最多 64 个字。同一账本继续允许重名。
- 「盘点金额可以为 0」包括新记一笔盘点、修改已有盘点，以及编辑已有资产时把当前金额改成 0。新登记一笔资产时，当前金额仍须大于 0。
- 0 表示价值为零，资产和历史都保留。去掉整笔资产仍然使用删除，不因为金额变成 0 而自动消失。
- 负债与非负债的划分、四笔钱、成员筛选、隐藏成员、只剩一条盘点不能删除、同一天取最后保存的盘点，都保持现有规则。变化只在于金额 0 是合法盘点。
- 没有盘点的月份继续视为没有数据。只有确实记下 0 的日期，才在合计和历史里显示 0。
- 上一次金额为 0 时，百分比没有意义，所以只显示变化额。
- 用户手册需要同步上述两处说法，避免手册仍写「盘点金额必须为正数」。
