# Contract: 服务端改写后的行为保持不变

本契约约束这次源码改写对使用者和发布人员可见的结果。不新增路径，不删除字段，不改变失败原因。实现细节以 [research.md](../research.md) 为准。数据以 [data-model.md](../data-model.md) 为准。

## 对外接口

- 前缀仍是 `/api/v1`。电脑网页和小程序继续用原来的地址，不更换根路径或端口。
- 已有请求的必填项、已有响应字段、用户能看懂的失败原因与改写前一致。
- 未登录就做需要登录的操作时，仍按改写前的方式拒绝，不换成未捕获异常的技术页面。
- 不恢复 `/mobile/`。该路径仍按已关停的部署处理，与本次无关。

## 进程与配置

| 项 | 改写后仍成立 |
|----|----------------|
| 监听端口 | 默认 `3000`，可由 `PORT` 覆盖 |
| 进程名 | `bill-manage` |
| 密钥与数据库口令 | 只放在 `server/.env` 或进程环境，不进入可提交源码 |
| 访问日志 | `server/logs/access.log` |
| PM2 日志 | `server/logs/err.log`、`server/logs/out.log` |
| 缺少必填密钥或口令 | 进程打印错误并退出，不对记账请求提供服务 |

生产启动顺序：在 `server/` 安装依赖，编译通过，再按部署说明启动 PM2。编译失败时不得用旧的或残缺的产物当作本次发布。

## 类型检查

- 检查覆盖 [data-model.md](../data-model.md) 中「纳入」的源码。
- 出现明确的类型错误时，检查失败并指出位置。
- 依赖包缺少类型时，只在 `server/types/` 描述本仓库实际用到的调用。业务源码不得整文件放弃检查。
- 开发时的自动重启不是发布门禁。发布门禁是编译所含的类型检查。

## 明确不在本契约中的变化

- 不改数据库表。
- 不改电脑网页和小程序的请求代码。
- 不增加新的记账、分账、导出或登录能力。
