# 快速验收：后端按业务领域重组并补齐账本权限

**功能分支**: `022-backend-domain-modules` | **日期**: 2026-11-17

不新增自动化测试。每搬完一块，在 `server` 目录执行一次类型检查。负债补数只在删除补数文件之前做一次，对应任务 T042。文件删除之后的发布核对只看结果，不再重跑脚本。其余手工核对在全部任务完成后再做。

## 准备

1. 准备三个账号：账本创建者、普通成员、完全不属于该账本的人。账本里至少有一笔带金额和归属人的明细；若有照片，记下能否打开。
2. 另备一条「类型为负债、仍在使用、但未标成负债」的资产；若目标库已经没有这种行，补数应影响 0 行，验收改为抽查现有负债资产都已标成负债。
3. 电脑网页、手机网页、小程序源码应没有本次改动。用原来的地址访问。

## 类型检查

在 `server` 目录：

```bash
pnpm typecheck
```

必须通过。未通过不得当作可发布版本。

## 负债标记（仅 T042，删除补数文件之前）

在 `server` 目录，对目标库执行一次：

```bash
pnpm exec tsx database/services/runDebtBackfill.ts
```

然后确认：类型为负债且未删除的资产都已标成负债。之后仓库里不再保留 `assetDebtBackfill.ts` 与 `runDebtBackfill.ts`，启动和接口也不会再跑这段补数。后面的发布核对不得再执行上面的命令。

## 合法路径（必须与重组前一致）

用创建者或成员，按现在的客户端完成：

1. 登录或注册，完成滑块；小程序绑定微信后仍能进入。登录结果仍能用于后续请求。
2. 创建账本，确认仍带默认分类。创建者修改名称成功。邀请成员加入成功。
3. 记一笔支出。记账人修改并删除自己的明细。其他成员能看照片，不能增删。
4. 增改当年预算和计划。
5. 成员查看区间汇总和分账。
6. 查看资产列表、做一次盘点、查看或保存汇率、查看养老计划。
7. 智能解析分别覆盖：未配置、超过当日额度、解析成功。未确认的结果不会变成一笔账。

## 权限路径

用「完全不属于该账本的人」携带该账本编号：

1. 流水列表、当月支出、导出、导入、新增、编辑、删除、区间收支、近三年支出：失败，说明为「不是该账本成员」，响应中没有该账本的金额或明细。
2. 预算、计划：失败，说明仍是「该用户并未加入此账本」。
3. 账本详情：失败，说明仍是「找不到账本」。
4. 家庭资产：失败，说明仍是「无权查看该账本」。
5. 分账：失败，说明仍是「不是该账本成员」。
6. 智能解析：失败，说明仍是「无权访问该账本」。
7. 修改账本名称：失败，说明为「不是该账本成员」，名称不变。
8. 查看该账本的照片：失败，说明仍是「无权查看」，响应中没有该账本的金额或明细。上传照片：失败，说明仍是「未找到账本」。

用普通成员：

1. 修改账本名称：失败，说明为「只有账本创建者才能修改账本名称」，名称不变。
2. 管理类型：失败，说明仍是「只有账本创建者才能管理类型」。
3. 管理概览规则：失败，说明仍是「只有账本创建者才能管理概览规则」。
4. 编辑或删除创建者记下的明细：失败，说明仍是「只能编辑自己记的账单」或「只能删除自己记的账单」，原明细不变。
5. 查看流水、概览、预算、计划和资产：成功。

再用不属于该账本的人新建自己的账本、查看自己的账本列表，并凭有效邀请加入：这三件事必须成功。

身份：登录者是甲，请求里另写乙的用户编号，至少 5 次读或改。结果必须仍按甲的权限，不能读到仅乙能看的账本。

用错方法调用一个存在的地址：结果要能看出是方法不对，而不是没有这个地址。
