# 数据模型：概览按累计收入分账

**功能分支**: `025-cumulative-income-split` | **日期**: 2026-11-20

不新增表，不改记账、成员、概览规则或年度配置的存储。下面是这一次查询里的范围和展示对象。

## 支出区间

用户在概览上选择的闭区间。

| 字段 | 说明 |
|------|------|
| 开始 | 当天 00:00:00.000 |
| 结束 | 当天 23:59:59.999 |

开始不得晚于结束。电脑端沿用现有时间戳，手机沿用 `YYYY-MM-DD`，服务端解析成上述两端。它决定总支出、总投资、总消费、垫付、支出结构、分类笔数和分类明细。

## 收入区间

服务端推导的分账用收入范围。未打开累计收入时，两端等于支出区间。

打开且支出开始、结束落在同一个自然年时：

- 开始 = 支出开始时间所在自然年的 1 月 1 日 00:00:00.000
- 结束 = 支出结束时间戳

因此收入区间包含支出区间。两端时间戳相同的，结算数字与关闭开关相同。它决定总收入、归属人收入、有效收入和分账权重。

支出跨年时不允许打开。已打开再改成跨年，视为关闭。

## 累计收入开关

当前这次查看的页面状态，不是账本数据。

| 状态 | 行为 |
|------|------|
| 关闭 | 默认。不传累计标志，或显式传关闭 |
| 打开 | 仅当支出区间在同一个自然年。离开页面、切换账本后回到关闭 |

不得写入数据库，不得出现在概览规则里。

## 归属人收入

某一当前成员在所用收入范围内的收入合计。只累计归属人是该成员的收入。公共归属和非当前成员不计入。金额大于 0 才展示，文案为「成员名收入」，例如「甲收入」。同一成员一行，不带记账人。顺序按账本成员既有顺序，即 `bill_users.id` 升序。

所用范围：开关打开且收入区间更长时用收入区间，否则用支出区间。

## 有效收入

归属人收入减去启用中的概览规则扣减。

- 数量乘单价：只使用支出所在自然年已保存的数量和归属，不按天数折算。没有配置时数量为 0。
- 指定支出类型：扣收入区间内该类型的个人支出和多人支出。公共支出不扣。落在支出区间外的只影响权重。
- 小于 0 的有效收入不展示，分账权重按 0。
- 全体权重都是 0 时，当前成员均分。多人归属只在选中的人之间分；这些人都是 0 时在组内均分。

页面不列出有效收入。它只参与分账权重。

## 结算建议

垫付减去应承担之后的转账或结清说明。句子只允许「无需分账」「双方结清，无需转账」「各方结清，无需转账」，或「某成员 → 某成员 转 x.xx 元」。

两个区间不同时，公共支出和同一组多人支出先加总，用收入区间的一组权重只分一次。只归属一个人的支出全额算在该成员头上。报销进度不改变是否参与分账。

## 校验

| 条件 | 结果 |
|------|------|
| 不是该账本成员 | 「不是该账本成员」，与现在相同 |
| 累计标志不是打开或关闭 | 「按累计收入分参数不正确」，无结算 |
| 打开累计收入且支出跨年 | 「跨年时不能按累计收入分」，无结算 |
| 请求里带了临时数量 | 忽略，不报错，不覆盖已保存配置 |
| 区间内没有收支 | 汇总数为 0，结算按现有空区间规则，不报错 |
