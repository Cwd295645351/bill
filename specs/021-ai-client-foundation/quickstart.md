# 快速验收：统一 AI 调用底座（E1）

**功能分支**: `021-ai-client-foundation` | **日期**: 2026-11-11

手工验收指南。契约见 [contracts/ai-parse-batch.md](./contracts/ai-parse-batch.md)；数据与审计字段见 [data-model.md](./data-model.md)。

## 前置条件

1. 本地已启动 API（`server/`）与 PC 前端（`frontend/`，`/pc/`）。
2. Redis 可用（与现网 session 相同配置）。
3. 准备：已配置 `AI_API_KEY` 的环境，以及可临时去掉 Key 的未配置环境（或本地另起一份）。
4. 至少两个登录用户 A、B（可同账本）；A 用于额度与审计，B 用于「互不影响」。

## 启动（示例）

```bash
# 终端 1：API
cd server && pnpm run dev

# 终端 2：PC
cd frontend && pnpm run dev
```

按本机方式登录并进入某一账本「记账」页。

## 主路径验收

### V1 — 批量解析零回归（SC-001）

1. 确认 `.env` 已配置 AI。
2. 以 A 进入账本 → 支出 → 批量解析，粘贴多行（含金额）。
3. 点「解析」→ 核对表格 → 可改字段 →「批量保存」。
4. **期望**：出草稿且未点保存前无新明细；保存后字段与手工录入规则一致；报销等默认与现网一致。

### V2 — 未配置友好失败（SC-002）

1. 去掉或清空 `AI_API_KEY` 后重启 API。
2. 再次批量解析。
3. **期望**：提示需联系管理员配置 AI；无新明细；服务端审计为 `not_configured` 且 **额度计数不增加**。

### V3 — 日额度限流（SC-003）

1. 恢复 AI 配置。将 `AI_DAILY_LIMIT` 临时设为较小值（如 `2`）并重启。
2. 以 A 连续成功触发解析（或触发会打上游的请求）至上限。
3. 再点一次解析。
4. **期望**：PC 弹出过于频繁/稍后再试类提示；**不**打上游；额度不因该次拒绝再增加。
5. 以 B 解析同一账本。
6. **期望**：B 不受 A 额度影响（按用户计量）。
7. **并发贴边（可选但推荐）**：将额度调到边界附近后，用两个近乎同时的解析请求压测；**期望**超额侧被拒（实现依赖 Redis 原子 `INCR`，不得「全部放过」）。若不便压测，核对 `rateLimit.ts` 为 `INCR` 后超限 `DECR` 即可视为通过。

### V4 — 审计可追溯且无密钥（SC-004）

1. 制造至少：1 次成功、1 次未配置或限流、1 次（可选）上游错误。
2. 在 API 日志中检索 `[ai-audit]`（或约定前缀）。
3. **期望**：能看到 `userId`、有传时的 `billId`、`upstreamRequested`、`outcome`/`errorCategory`、`durationMs`；全文检索无 API Key / Bearer token。

### V5 — 手册（FR-010）

1. 打开 `docs/用户手册.md` 批量解析小节。
2. **期望**：除未配置说明外，含过频/稍后再试类说明。

### V6 — 底座可扩展（SC-005）

1. 打开 `server/utils/ai/index.ts`（或 `client.ts`）中的扩展约定注释。
2. **期望**：写明后续能力复用超时/错误归类/审计/限流，业务侧只换提示词与结果处理；本期无第二套调用链路。

## 回归注意

- 输入校验（空文本、超过 100 行等）行为与现网一致，且此类失败不计 AI 日额度。
- H5 / 小程序本期无批量解析入口，不强制回归 AI；PC 单条记账、批量保存权限不变。
- Redis 不可用时 AI 路径应失败关闭（拒请求、不打上游）；本地验收可在停 Redis 后点解析确认（会话也可能受影响，以 API 进程日志与返回 `message` 为准）。

## 环境变量（本期）

| 变量 | 说明 |
|------|------|
| `AI_API_KEY` | 必填才可调用上游 |
| `AI_BASE_URL` | 可选，默认硅基流动 |
| `AI_MODEL` | 可选 |
| `AI_DAILY_LIMIT` | 可选，默认 60 |

验收结束后记得恢复生产合理的 `AI_DAILY_LIMIT`。
