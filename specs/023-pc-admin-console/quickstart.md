# 快速验收：PC 运营后台

**功能分支**: `023-pc-admin-console` | **日期**: 2026-11-18

对照 [spec.md](./spec.md)、[contracts/admin-api.md](./contracts/admin-api.md)、[data-model.md](./data-model.md)。

## 前提

1. `server/.env` 已配置 `ADMIN_USERNAME` 为某一已存在用户的 `username`。
2. 另有一个**非**该用户名的普通账号。
3. 后端与 PC 前端可本地启动；数据库可写（需能建表/加列）。
4. （可选）AI 已配置，便于产生审计样例；也可用限流/未配置路径造失败审计。请求必须带当前账本 `billId`。

## 启动

```bash
# 后端
cd server && pnpm typecheck && pnpm dev

# PC
cd frontend && pnpm dev
```

确认启动日志无补表失败；若 `catalog_defaults` 原为空，应已灌入与 `initDatas` 一致的种子。

## 场景 A：管理员总览与列表（P1）

1. 用管理员账号登录 PC，确认顶部出现「后台」，进入后看到总览。
2. 切换近 7 日 / 近 30 日，趋势重算且无自定义日期控件。
3. 用户列表默认无已删除；关键词能筛到已知用户；点进详情见账本与最多 20 条 AI。
4. 账本列表同理；详情仅成员昵称，无流水正文。
5. AI 审计列表倒序；按成败与关键词筛选有效；记录无密钥/prompt。

**期望**: 与样例数据一致；无审计窗口成功率显示「不适用」；SC-001 / SC-002 可勾选。

## 场景 B：非管理员拦截（P1）

1. 普通账号登录：无「后台」菜单。
2. 浏览器直接打开 `/layout/admin`（或当前后台路径）：应被拒或看不到数据。
3. 用普通账号 token 请求 `GET /api/v1/admin/overview`：`message` 为非管理员类，`data` 为空。

**期望**: SC-004。

## 场景 C：默认类型只影响新账本（P2）

1. 管理员改一条默认支出类型名称，再软删另一条（非最后一项）。
2. 关闭「显示已删除」看不到已删项；打开后只读可见、无恢复。
3. 用任意账号新建账本：类型名单 = 当前未删除模板。
4. 打开改动前已有账本：类型名与流水上的类型名快照不变。
5. 尝试删光某类最后一项：被拒绝。

**期望**: SC-005。

## 场景 D：AI 账本必填与零回归

1. 不传 `billId` 调 `parse-batch`：失败，不打上游；后台审计列表无对应记录（SC-003）。
2. 传他人账本 id：非成员失败（与现网一致）。
3. 普通用户记一笔、编辑自己的账、带账本的 AI 解析（若已配置）仍按原确认落库流程；PC 确认仍传当前 `billId`。
4. AI 日限额算法与改前一致（仅成功进入额度占用的路径计次）。
5. 管理界面与管理 API 无封禁、删账本、改额度等写入口（FR-016）。

**期望**: FR-019；SC-003；SC-006。

## 类型检查


（若前端无单独 tsc 脚本，以项目既有检查命令为准。）
