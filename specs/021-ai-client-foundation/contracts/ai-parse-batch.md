# 契约：AI 批量解析与底座行为

**基础路径**: `/api/v1`  
**响应形状**: `{ retCode, message, data }`（`ResModel`）；成功 `retCode === 0`，失败 `retCode === 1`（或既有非 0）。  
**鉴权**: 需登录（JWT）；`userid` 由服务端从 JWT 注入，**忽略**请求体中的身份伪造字段。

## `POST /api/v1/ai/parse-batch`

### 请求体

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| text | string | 是 | 多行支出文本；空/超长等校验与现网一致 |
| costTypes | array | 是 | 支出类型清单；过滤 hidden 等规则与现网一致 |
| billId | string | **否** | 当前账本；若提供则必须为调用者所属账本 |

### 成功响应（形状不变）

- `data`: 数组，元素含 `index`、`costTypeId`、`costTypeName`、`money`、`date`
- **不**自动写入记账明细

### 失败响应（兼容扩展）

| 情况 | `message` 方向（可微调措辞，须可读） | 上游 | 计次 |
|------|--------------------------------------|------|------|
| 未配置 AI | 「AI 服务未配置，请联系管理员」 | 否 | 否 |
| 日额度用尽 | 「AI 调用过于频繁」类，提示稍后再试/次日再试 | 否 | 否 |
| 额度存储不可用 | 「服务繁忙/稍后再试」类（失败关闭） | 否 | 否 |
| 超时 | 「AI 服务请求超时…」 | 是 | 是 |
| 上游 HTTP 失败 | 「AI 服务请求失败…」 | 是 | 是 |
| 解析失败 | 「AI 解析失败…」 | 是 | 是 |
| billId 非成员 | 无权/非成员类提示 | 否 | 否 |
| 既有输入校验 | 与现网相同（空文本、行数等） | 否 | 否 |

成功时 `data` 数组字段**不得删除或改名**；不得为限流/审计新增破坏性必填响应字段（若未来加 `errorCategory` 只能是可选扩展，本期可不加）。

## 服务端底座约定（非新公开路径）

本期不新增对外 HTTP 路径；下列为内部行为合同，供实现与验收：

1. 所有外部 Chat Completions 调用经统一 AiClient（超时可配置、默认批量 5 分钟）。
2. 每次经入口且会打上游的调用写 `[ai-audit]` 结构化日志；字段见 [data-model.md](../data-model.md)。
3. 日额度：每用户 × 东八区自然日；默认上限 60（`AI_DAILY_LIMIT` 可覆盖）；**无**短时突发限额；Redis 不可用时失败关闭（不打上游、不计次）。
4. 路由编排顺序：输入校验 → 可选 billId 成员校验 → 未配置 → 日额度占用 → 上游 → 审计。
5. 密钥仅环境变量；日志与错误体不得含密钥。

## PC 客户端约定（最小）

- `frontend` 批量解析请求在已进入账本的前提下**应传**当前 `billId`。
- 继续用接口返回的 `message` 做 `ElMessage` 展示；限流无需新弹窗组件。
- 不改变「解析 → 表格核对 → 批量保存」确认落库流程。
