# 实现计划：概览按累计收入分账

**功能分支**: `025-cumulative-income-split` | **日期**: 2026-11-20 | **规格**: [spec.md](./spec.md)

**输入**: `/specs/025-cumulative-income-split/spec.md` 中的功能规格

**说明**: 本文件由 `/speckit-plan` 填写；其定义描述执行工作流。

## 摘要

三端概览增加开关「按累计收入分」。关闭时仍按支出区间自己的收入分账。打开且支出区间在同一自然年时，支出、垫付、结构和分类仍看支出区间，权重改用该年 1 月 1 日至支出结束日的有效收入。收入区间由服务端推导，页面不能另填起止日，也不记住开关。两个区间不同时只在开关下写明收入区间，不列出每人有效收入。名称与金额分行。跨年时关掉开关，按现有按年合并结算。

技术路径：`POST /api/v1/overview/settlement` 与 `GET /api/v1/overview/mobile` 增加可选布尔值 `cumulativeIncome`。不新增路径。结算成功体只追加四个日期，原有字段保留。请求里的 `quantityInputs` 不再参与结算。总支出、总投资、总收入继续走现有收支汇总。归属人收入改由结算结果里的成员毛收入按人合并。详见 [research.md](./research.md)。

## 技术上下文

**语言/版本**: TypeScript。后端 Node.js + Koa 2（`server/`）；电脑端 Vue 3 + Vite（`frontend/`）；H5 Vue 3（`mobile-h5/`）；小程序原生 + TypeScript（`miniapp/`）。

**主要依赖**: 现有 `getBlance`、`buildSettlement`、`getSettlement`、`getMobileOverview`。自然年切分继续用现有 `yearSegments` 的 dayjs。不新增图表库，不新增表。

**存储**: 继续使用记账、账本成员、概览规则和年度配置。开关不入库。无迁移。

**测试**: 无新测试框架。按 [quickstart.md](./quickstart.md) 手工验收，对照 [contracts/overview-cumulative-income.md](./contracts/overview-cumulative-income.md)。用规格中的甲乙示例对三端。

**目标平台**: 电脑网页 `/pc/`、移动端 H5 `/mobile/`、微信小程序。后端公开前缀仍是 `/api/v1`。

**项目类型**: monorepo 增量。改 `server/modules/overview`、电脑端概览页、H5 概览页、小程序概览分包，并更新用户手册第 7.1 节和第 11.3.1 节。

**性能目标**: 一次查询仍在正常家庭账本的数据量下随手完成。电脑端两个区间不同时最多两次收支汇总加一次结算，三次都返回后才刷新；后一次查询不得被先发出的响应覆盖。手机仍是一次概览请求。

**约束**: 不恢复旧 `mobile/`。不改近五年趋势、预算、家庭资产和记账归属。不提供收入起止日输入。跨年不得按累计收入分。数量不按天数折算，也不再接受临时数量覆盖。总投资仍只含基金（类型 id `1015`）。

**规模/范围**: 一个可选查询标志，一套分账分支，三端各加一个开关和分行版式。不新增页面。

### 设计后复核

收入区间只在服务端按支出开始日所在自然年的 1 月 1 日至支出结束日推导，与现有按年切段使用同一个 dayjs。两个区间的时间戳相同，或未打开开关时，仍走现在的按年合并。更长时，收入区间的记账只算收入和指定类型扣减，支出区间的记账只参与分摊，一组权重只分一次。

总支出、总投资、总收入继续调用 `getBlance`。电脑端在区间不同时对支出区间和收入区间各查一次汇总；归属人收入和有效收入以结算结果为准，不再使用汇总里按记账人拆开的明细。手机主接口在服务端完成这两次汇总。分类明细和近五年不读这个开关。资产对账继续直接调用 `buildSettlement`，不传累计标志。

实现顺序建议：结算分支与契约 → 手机聚合 → 电脑端开关和版式 → H5 → 小程序 → 用户手册 → 按快速验收对三端。

## 复杂度跟踪

| 违规项 | 为何需要 | 更简单方案及否决原因 |
|--------|----------|----------------------|
| 结算忽略请求里的临时数量 | 规格要求开不开开关都只用已保存年度配置。现有页面已经不传 | 保留「传来就整段覆盖」会让累计收入被临时数量改掉，而页面上没有这项输入 |
| 电脑端区间不同时查两次收支汇总 | 总收入含公共归属，结算里的成员收入不含。两类数都要 | 只用结算成员收入冒充总收入，会和现在的总收入口径不一致 |
| 三端都改分行版式 | 规格要求开关开或关，名称和金额都分行 | 只在打开开关时分行，关闭时仍是旧版式，三端对不齐 |
