# Data Model: 服务端源码改为 TypeScript

本次不新增、不修改、不删除任何持久化数据。下表只说明现有对象在源码改写后必须保持的状态。字段含义与今天的模型一致，不在这里重列。

## 不变量

- 不执行 SQL，不调整 `sequelize.sync()` 会创建或对齐的表、列和索引。
- 不改账号、微信绑定、账本、成员、明细、预算、计划、资产和图片记录的存法。
- 记账人、归属人、分享码、谁可以改删明细，判断与改写前相同。
- 已加密内容仍用 `server/.env` 里的 `AES_KEY` 与 `AES_IV` 读取。不更换算法，不要求重新录入。
- 编译产物 `server/dist/` 不是数据，不入库，由 `.gitignore` 忽略，每次发布重新生成。

## 实体

### 账号与微信绑定

登录身份，以及小程序 openid 与账号的一对一绑定。

- 改写不新建、不删除账号，不提供解绑。
- 已签发的登录在原有效期内仍然有效，因为签名密钥不变。
- 小程序已绑定的用户打开后仍按原方式自动登录。

### 账本与成员

联合记账的隔离单位，以及其中的人。

- 成员名单不因服务端换语言而变化，不要求重新加入。
- 不同账本的成员、类型、预算、计划和明细仍然互不影响。

### 收支明细

账本中的支出和收入。

- 金额、记账人、归属人与改写前一致。
- 仍只有记账人可以编辑或删除自己的明细。

### 预算、计划、资产与图片

已提供的账本附属数据。

- 改写后仍按原方式读写。
- 不新增能力，也不下线导出、图片和智能解析。

## 源码集合（非持久化）

类型检查和编译覆盖的是服务端运行时源码，不是上表里的业务数据。

| 纳入 | 不纳入 |
|------|--------|
| 启动入口、应用组装、路由、服务、模型、工具、会在进程里执行的配置模块 | `node_modules/`、日志、`server/.env`、SQL、`pm2.conf.json`、`prettier.config.js` |

最终状态下，纳入范围内不再保留需要维护的 JavaScript。`prettier.config.js` 继续用 JavaScript，因为它只给格式化工具读取，不参与记账进程。
