# Contract: 小程序编辑记账的日期

## 界面

适用页面：微信小程序「编辑记录」。账本流水和搜索结果进入的是同一个表单。

| 时机 | 日期格必须显示 | 提交给已有编辑接口的日期 |
|------|----------------|--------------------------|
| 刚打开，原自然日不是今天 | 原自然日，格式 `YYYY-MM-DD` | 尚未提交 |
| 刚打开，原自然日就是今天 | 今天 | 尚未提交 |
| 未改日期就保存 | 仍是原自然日 | 该自然日 00:00 的毫秒时间戳，日历日与打开前一致 |
| 用户改了日期再保存 | 用户选的那一天 | 所选自然日 00:00 的毫秒时间戳 |
| 原日期无法格式化成 `YYYY-MM-DD` | 不得显示成今天来冒充原日期 | 不得提交今天。保存前提示，不发出编辑请求 |
| 未保存就离开，或保存失败 | — | 不产生新的日期 |

新增记账不走上表。打开时日期仍默认今天；用户改过则提交所选自然日。

其它回填不变：金额、支出或收入、分类、归属人、内容、报销进度。记账人不可改。不是记账人不能提交编辑。

## 已有编辑接口（不改）

客户端继续调用现有的编辑记账接口，不新增路径，不新增字段，不改变日期单位。

- 日期字段仍叫 `date`。
- 值仍是自然日开始的毫秒时间戳，与现在新增记账所用的单位相同。
- 未改日期时，客户端必须提交**原自然日**的时间戳，而不是请求里省略日期，也不是改由服务端猜测。
- 服务端仍按「请求里的日期就是要保存的日期」处理。权限、账本隔离、记账人不可改，都保持现状。

电脑网页端和手机网页端继续用各自现有的编辑请求，本契约不要求它们改动。
