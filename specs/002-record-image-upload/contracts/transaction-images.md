# Contract: 记账照片

基础路径 `/api/v1`。登录方式与现有记账接口相同。响应仍是 `{ retCode, message, data }`。本文件只描述这次新增或扩展的部分。数据规则见 [data-model.md](../data-model.md)。

现有新增、编辑、删除、列表的路径不变。未提到的字段保持原样。手机网页端不调用这些新行为。

## 上传一张照片

`POST /api/v1/transaction/image`

`multipart/form-data`：

| 部分 | 必填 | 说明 |
|------|------|------|
| file | 是 | 一张照片 |
| billId | 是 | 要挂向的账本 |

调用者必须是该账本成员。成功后照片处于「已上传未挂接」，不会出现在任何一笔的列表里。

成功时 `data`：

```json
{ "id": "照片 id" }
```

失败时 `retCode` 非成功，`message` 用使用者能看懂的话：

| 情况 | message |
|------|---------|
| 不是该账本成员 | 未找到账本 |
| 超过 10MB | 单张照片不能超过 10MB |
| 不是 JPEG、PNG、GIF、WebP | 无法当作照片打开 |
| 对象存储写入失败 | 照片没有保存成功 |

## 新增记账时挂上照片

`POST /api/v1/transaction`

在现有字段之外，可以多传可选的 `imageIds`：按顺序排列的照片 id 数组。不传则与今天一样，不挂照片。

仅当数组里的每一张都同时满足下面条件时，才和这笔新账一起保存成功：

- 属于当前 `billId`
- 上传人就是本次记账人
- 尚未挂到别的记账
- 仍可挂接
- 总数不超过 9

任一条件不满足，或新增本身失败：不产生这笔账，这些照片保持未挂接，列表里看不到。

成功时响应与今天相同（`data` 仍为空，`message` 为新增成功）。不要为了返回新 id 而改掉这个形状。

## 编辑记账时替换照片

`PUT /api/v1/transaction`

可选字段 `imageIds`：

| 请求 | 结果 |
|------|------|
| 不传 `imageIds` | 已有照片完全不动。手机网页、旧客户端走这条 |
| 传入数组 | 保存成功后，这笔账的可查看照片变成且只变成这个顺序。空数组表示清空 |
| 数组超过 9 张，或混入别人的、别的账本的、已挂到别笔的 id | 整次编辑失败，原照片不变 |

其它编辑规则不变：只有记账人本人可以成功；未改的金额、日期、分类、归属人、备注保持原值。照片保存失败时，这次编辑整体失败，已填内容由客户端留在表单上。

## 列表里的照片

`POST /api/v1/transaction/list`

每条记账多一个字段：

```json
{
  "images": [
    { "id": "照片 id", "sort": 0, "viewUrl": "https://接口域名/api/v1/transaction/image/file?id=...&exp=...&sig=..." }
  ]
}
```

没有可查看照片时，`images` 为 `[]`。非该账本成员时，`images` 也是 `[]`，不给 `viewUrl`。原有的金额、日期、备注等字段不改名、不删。

`viewUrl` 的 `exp` 为 Unix 秒，有效期 2 小时。`sig` 由服务端用 `OSS_URL_SECRET` 对 `id` 和 `exp` 签名。地址里没有对象键，也没有对象存储密钥。

导出接口不增加照片列，也不读取 `images`。

## 打开照片

`GET /api/v1/transaction/image/file?id=&exp=&sig=`

不使用登录头，供小程序图片组件和电脑端图片标签直接打开。

放行条件全部满足：

- 签名正确且未过期
- 该行已挂到某笔记账
- `viewable` 为 true
- 该笔记账未删除

否则返回失败，不输出图片字节。成功时 `Content-Type` 为该行记录的图片类型，正文是图片内容。

## 删除记账

`DELETE /api/v1/transaction?id=`

路径与权限不变（仅记账人）。删除成功后，这笔账上的照片全部变为不可查看，上节的打开接口失败。

## 客户端不应做的事

- 电脑端新增请求不传 `imageIds`，新增表单上也没有选择照片的控件。
- 批量解析、Excel 导入不传 `imageIds`。
- 编辑时如果要保持原照片，必须把原来的 id 按原顺序放进 `imageIds`，不能靠「少传几张」来表示没改。少传表示拿掉没传的那几张。
