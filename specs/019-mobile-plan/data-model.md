# Data Model: 019-mobile-plan

本特性**无新 MySQL 表**；复用账本内既有计划结构（表 `bill_plan_buys`，经 `billService.savePlanBuy` 持久化）。下列为客户端与契约使用的逻辑模型。

## 实体：计划汇总（PlanBuy）

对应 `GET /plan/list` 在指定 `billId` 下的返回体。

| 字段 | 类型 | 说明 |
|------|------|------|
| count | number | 当前可见计划条数（与 details 长度一致或由服务端维护） |
| details | PlanItem[] | 可见计划列表；服务端已排除逻辑删除与「已购」 |

**空态**: `details` 为空时，UI 仍展示高 / 中 / 低三档分区，每档显示档内空态，并保留「新增计划」。

## 实体：计划条目（PlanItem）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 编辑 / 删除主键；列表返回后必须保留 |
| title | string | 标题；trim 后非空 |
| context | string | 内容；trim 后非空 |
| priority | 1 \| 2 \| 3 | 1=高，2=中，3=低 |

### 服务端持久化旁路字段（客户端本切片不展示、不写入业务表单）

| 字段 | 说明 |
|------|------|
| isBuy | 已购标记；列表接口已过滤为 false 的可见项；移动端不提供切换入口 |
| isDel | 逻辑删除；删除接口置 true；列表不可见 |

### 校验规则（与现网 / 澄清一致）

- `title`、`context` 去首尾空白后必须非空；空或纯空白 → 客户端拦截并提示；服务端亦拒绝空值。
- **不设**移动端专属字数上限（与 PC 一致）；既有库字段长度属后端既有边界。
- `priority` 必须为 1 / 2 / 3；非法或缺失不得保存。
- 新建默认 `priority = 1`（高）。
- 删除为逻辑删除且不可恢复；**不**影响任何记账明细。
- 仅账本成员可读写；非成员 → 服务端错误。

### 客户端派生（展示）

| 派生项 | 规则 |
|--------|------|
| 三档分组 | `priority===1` → 高；`2` → 中；`3` → 低；固定展示三档 |
| 同档顺序 | 按 `details` 遍历顺序依次 push，不重排 |
| 档色 | 高 `#f74f4f`；中 `#e6a23c`；低 `#18a356`（与原型一致，实现可微调但语义不变） |
| 档内空态 | 该档无条目时展示「这一档还没有」 |

## 实体：账本（Bill）

计划按账本隔离；页面始终带 `billId`。本切片不改变成员 / 邀请模型。

## 关系

```text
Bill 1 ── * PlanItem（可见子集：!isDel && !isBuy）
```

计划与 `Transaction` **无外键、无自动联动**。

## 状态与生命周期

```text
[新增] → 可见计划（isBuy=false, isDel=false）
         ├─ 编辑标题/内容/优先级 → 仍可见；priority 变更则换档展示
         └─ 删除确认 → isDel=true → 列表不可见（不可恢复）
```

「已购」若由其它路径置位，则不再出现在 list；本切片不提供该路径。
