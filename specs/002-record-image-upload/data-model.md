# Data Model: 记账照片

照片是记账明细上的附加内容。记账主表的列不改。规则与 [spec.md](./spec.md) 一致，接口形状见 [contracts/transaction-images.md](./contracts/transaction-images.md)。

## 记账明细（已有，不改列）

表 `transactions`。与照片有关的只是它的身份和是否已删除。

| 字段 | 含义 | 本次 |
|------|------|------|
| id | 记账 id | 不改 |
| bill_id | 所属账本 | 不改。照片不能跨账本 |
| user_id | 记账人 | 不改，也不可被编辑改掉。只有这个人能增删照片 |
| is_del | 是否已删除 | 为 true 时，挂在它上面的照片都不可查看 |
| 金额、日期、收支、分类、归属人、备注等 | 原有含义 | 不因照片改变 |

没有照片的记账仍然是完整的一笔。导出、预算、概览继续只读这些原有列。

## 记账照片（新增）

表 `transaction_images`。一行一张照片。启动时由现有的 `sequelize.sync()` 建表。回滚时删除这张表即可，不改 `transactions`。

| 字段 | 类型 | 约束 |
|------|------|------|
| id | CHAR(36) | 主键 |
| bill_id | CHAR(36) | 必填。必须与所属记账的账本一致 |
| transaction_id | CHAR(36)，可空 | 空表示已上传但还没挂到任何一笔可见记账上 |
| user_id | CHAR(36) | 必填。上传人。只能挂到他自己记的那一笔 |
| object_key | STRING | 必填。对象存储里的私有对象键，不返回给客户端 |
| sort | INTEGER | 从 0 起，与用户选择顺序一致 |
| size | INTEGER | 字节数，1 到 10485760 |
| content_type | STRING | 仅 `image/jpeg`、`image/png`、`image/gif`、`image/webp` |
| viewable | BOOLEAN | 默认 true。从记账拿下或整笔删除后改为 false |
| created_at | DATETIME | 上传成功的时间 |

索引：`transaction_id`，以及 `bill_id + user_id`（用来核对未挂接的照片）。

### 校验

- 单张 `size` 不超过 10MB。文件头必须是 JPEG、PNG、GIF 或 WebP。
- 同一笔记账上 `viewable = true` 且已挂接的行最多 9 张。
- `sort` 在一次成功保存后是 0 到 n-1，与请求里的 id 顺序一致。
- `transaction_id` 若有值，该记账必须存在、未删除，且 `bill_id`、记账人与照片行一致。
- 未挂接的行（`transaction_id` 为空）不会出现在列表里，查看接口也不放行。

### 状态

```text
已上传未挂接 → 随新增或编辑保存成功 → 已挂接可查看
已挂接可查看 → 编辑时从列表去掉并保存成功 → 不可查看
已挂接可查看 → 整笔记账删除成功 → 不可查看
已上传未挂接 → 新增或编辑失败 → 保持未挂接，成员不可见
```

不可查看之后不再回到可查看。对象存储里的文件在标记不可查看之后尽力删除，删失败也不恢复为可查看。

## 关系

- 一笔记账明细有 0 到 9 张可查看的照片。
- 一张照片最多属于一笔记账，且必须属于同一个账本。
- 账本成员可以查看已挂接的照片。只有记账人可以改变这个集合。
- 电脑端新增不创建照片行。小程序新增只有在全部上传成功后才把未挂接的行挂上。

## 列表上的附加字段

查询记账列表时，给每一笔加上 `images` 数组（没有照片就是空数组）。元素只有 `id`、`sort`、`viewUrl`。这是多出来的字段，不替换金额、备注等原有字段。非该账本成员拿到的 `images` 为空数组，不带可打开的地址。
