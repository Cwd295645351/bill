# Feature Specification: 移动端预算模块

**Feature Branch**: `017-mobile-budget`

**Created**: 2026-11-10

**Status**: Draft

**Input**: User description: "根据原型 `prototypes/miniapp.html` 实现预算模块"

## 背景与边界

当前产品中，预算的查看与增删改仅在 PC 端完整提供；微信小程序与移动端 H5 的账本明细页仅展示「剩余预算」汇总数字，用户手册也写明预算编辑请到电脑完成。

`prototypes/miniapp.html` 已把预算做成账本内一级能力：进入账本后底部可切换「记账 / 概览 / 预算 / 计划 / 资产」，预算页支持当年汇总、占比饼图、按支出类型的进度卡片，以及新增、编辑、删除，并可从卡片下钻到「搜索记录」页（预填该支出类型与当年起止日期并自动搜索）。

本规格交付**移动端（微信小程序 + 移动端 H5）预算模块**，交互与信息架构以该原型为准，业务口径与现有 PC 预算保持一致。本切片**不包含**概览、计划、家庭资产的移动端实现。

## Clarifications

- Q: 本切片验收通过时，微信小程序与移动端 H5 是否必须都已交付可用的预算模块？ → A: 两端都必须完成才算本切片交付完成
- Q: 用户点击预算卡片空白处下钻时，应打开哪一类记账视图？ → B: 打开搜索页，预填该支出类型与当年起止日期
- Q: 从预算卡片下钻进入搜索页后，是否自动执行搜索？ → A: 预填后自动搜索并展示结果（无匹配则空态）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在手机上查看当年预算进度 (Priority: P1)

已登录且至少加入一个账本的用户，进入某个账本后切换到「预算」，看到当年年度预算、年度支出、各类型预算占比，以及每条预算的花费进度与状态文案，用于判断消费节奏。

**Why this priority**: 没有可读的进度视图，移动端预算就没有日常价值；这是最小可用交付。

**Independent Test**: 在已有当年预算数据的账本中打开预算页，即可独立验收汇总、饼图与卡片展示，无需先完成新增流程。

**Acceptance Scenarios**:

1. **Given** 用户已进入某账本，**When** 点底部「预算」，**Then** 进入预算页，标题为「预算」，底部仍保留账本内五个入口（记账 / 概览 / 预算 / 计划 / 资产）且「预算」高亮。
2. **Given** 用户在账本内底部导航，**When** 点「概览」「计划」或「资产」，**Then** 进入对应未交付占位页并提示请到电脑端查看或管理；入口保持可点外观（不置灰、不隐藏）；占位页不得展示已交付的业务内容。
3. **Given** 该账本当年已有至少一条预算，**When** 打开预算页，**Then** 顶部展示当前自然年、年度预算合计、年度支出合计；有预算时展示「预算占比」饼图与图例百分比。
4. **Given** 某支出类型已设预算，**When** 查看对应卡片，**Then** 类型名在左侧、状态文案在右侧；同一行展示「预算」金额与「花费」金额；下方一条进度条按花费/预算比例着色与封顶显示。
5. **Given** 花费已超过预算，**When** 查看该卡片，**Then** 进度条最多到 100%，花费数字仍大于预算并按超支样式强调；状态为「即将或已经超支」。
6. **Given** 该账本当年没有任何预算，**When** 打开预算页，**Then** 显示空态「今年还没有预算」，不展示占比饼图，仍可看到底部「新增预算」。

---

### User Story 2 - 新增、编辑、删除当年预算 (Priority: P1)

账本成员在手机上为当年某个支出类型设定或调整预算金额，或删除不再需要的预算条目；删除不影响已有记账。

**Why this priority**: 原型把移动端预算做成可管理能力；若只能看不能改，仍要回 PC，无法兑现原型目标。

**Independent Test**: 从空预算账本新增一条、再编辑金额、再删除，可完整验收，不必依赖下钻跳转。

**Acceptance Scenarios**:

1. **Given** 用户在预算页，**When** 点「新增预算」，**Then** 打开表单：可选支出类型、可填金额；提示金额须大于 0，同一类型一年只设一条，删除不影响已有记账。
2. **Given** 新增表单中，**When** 选择支出类型，**Then** 列表仅包含本账本未隐藏、且当年尚未设置预算的支出类型。
3. **Given** 用户未选类型或金额 ≤ 0，**When** 点保存，**Then** 不保存并给出明确提示。
4. **Given** 用户选了合法类型且金额 > 0，**When** 保存成功，**Then** 关闭表单，列表出现该卡片，花费初始为当年该类型已发生支出（无支出则为 0），汇总与饼图随之更新。
5. **Given** 已有预算卡片，**When** 点「编辑」，**Then** 可改金额，支出类型只读不可改；保存后金额与进度更新。
6. **Given** 已有预算卡片，**When** 点「删除」并确认，**Then** 该条预算从当年列表消失，已有记账不变；取消确认则不做删除。

---

### User Story 3 - 从预算卡片下钻到当年该类型记账 (Priority: P2)

用户在看进度时想核对具体花了什么，点卡片空白区域进入搜索页，预填该支出类型与当前自然年的起止日期，并自动执行一次搜索以展示对应流水（无匹配则空态）。

**Why this priority**: 强化「看进度 → 查明细」闭环，但对「能设预算、能看进度」的 MVP 不是阻断项。

**Independent Test**: 在已有预算与对应支出的账本中，点卡片非操作按钮区域，验证进入搜索页、条件已预填且已直接展示筛选结果（或空态）。

**Acceptance Scenarios**:

1. **Given** 某类型预算卡片已展示，且当年该类型有支出，**When** 用户点击卡片空白处（非「编辑」「删除」），**Then** 进入该账本「搜索记录」页，预填收支为支出、支出类型为该预算类型、起止日期为当前自然年首末日，并自动完成一次搜索，列表仅含符合条件的记录。
2. **Given** 某类型预算卡片已展示，且当年该类型无支出，**When** 用户点击卡片空白处下钻，**Then** 仍进入搜索页并完成自动搜索，展示无结果空态（不得假装有数据）。
3. **Given** 用户从预算下钻进入搜索页，**When** 返回，**Then** 可回到预算页或账本内导航，不丢失当前账本上下文。

---

### User Story 4 - 小程序与 H5 能力对齐 (Priority: P2)

同一账本的预算数据在微信小程序与移动端 H5 均可查看与管理，两端信息结构与操作结果一致；两端仅在登录/邀请等既有差异上不同，预算业务本身无端侧特例。

**Why this priority**: 原型明确「同一份稿同时覆盖小程序与 H5」；本切片以两端都可用为交付完成条件。

**Independent Test**: 分别在小程序与 H5 对同一账本执行查看与增删改，对比结果与 PC 当年预算一致；任一端缺失则本切片未完成。

**Acceptance Scenarios**:

1. **Given** 用户在 PC 为某账本当年新增一条预算，**When** 在小程序与 H5 分别打开该账本预算页，**Then** 两端都能看到同一条预算及一致的花费进度口径。
2. **Given** 用户在 H5（或小程序）修改或删除一条预算，**When** 在另一移动端或 PC 刷新预算，**Then** 变更已生效。
3. **Given** 用户使用小程序或 H5，**When** 使用预算页，**Then** 不出现仅某一端才有的预算业务字段或互斥规则。
4. **Given** 进行本切片验收，**When** 仅有一端完成预算模块，**Then** 不得判定本切片交付完成。

---

### Edge Cases

- 当年该类型已有预算时，新增列表不再出现该类型；若仍尝试重复新增，系统拒绝并展示服务端返回文案（现网为「已存在相关预算」或等价提示）。
- 支出类型在电脑端被隐藏后，不得再被选为新增预算类型；已存在的历史预算条目仍可编辑金额或删除（与 PC 既有习惯对齐：已设预算仍可见）。
- 预算金额必须为正数；非法输入不可保存。
- 花费为 0 时进度为 0，状态为「较宽裕」。
- 预算只做提醒，不阻止继续记账（与现有产品一致）。
- 用户不是该账本成员、或未登录时，不能查看或改该账本预算。
- 切换自然年后，页面加载「当前年」数据；本切片不要求移动端提供跨年切换器（与原型一致，打开即当年）。
- 删除预算需二次确认；误触取消不得删除。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 微信小程序与移动端 H5 MUST 均在账本内提供「预算」入口（账本内底部导航之一），进入后展示当前自然年的预算管理页；本切片交付完成的前提是两端预算模块均可用。
- **FR-002**: 预算页 MUST 展示年度预算合计、年度支出合计；有预算明细时 MUST 展示各支出类型预算金额的占比饼图与图例。
- **FR-003**: 每条预算 MUST 以卡片展示：类型名左对齐、状态文案右对齐；预算金额与花费金额同一行；一条花费进度条；「编辑」「删除」操作按钮等宽样式一致。
- **FR-004**: 花费进度状态文案与色阶 MUST 与下列区间一致：&lt;25% 较宽裕；25%～50% 正常；50%～75% 注意节奏；75%～90% 接近上限；≥90% 即将或已经超支。进度条展示宽度封顶 100%，花费数字可超过预算。
- **FR-005**: 账本成员 MUST 能新增当年预算：选择未占用的可见支出类型，输入大于 0 的金额并保存；同一账本同一自然年同一支出类型最多一条。
- **FR-006**: 账本成员 MUST 能编辑已有预算的金额（类型不可改），并 MUST 能在确认后删除预算；删除 MUST NOT 影响已有记账明细。
- **FR-007**: 点击预算卡片空白区域 MUST 打开该账本「搜索记录」页，并预填：收支为支出、支出类型为该预算类型、开始日期与结束日期为当前自然年首末日；进入后 MUST 自动执行一次搜索并展示结果（无匹配则空态）；MUST NOT 打开账本明细页作为下钻目标，也 MUST NOT 仅停在未搜索的表单页。
- **FR-008**: 移动端预算的数据口径（自然年、按支出类型、花费来自当年该类型支出合计、账本隔离）MUST 与现有 PC 预算一致，使同一账本在多端看到的预算与花费一致。
- **FR-009**: 本切片 MUST NOT 实现移动端概览、计划、家庭资产的业务能力；账本底部仍 MUST 展示五个入口；「概览 / 计划 / 资产」被点击时 MUST 提示请到电脑端查看或管理——**小程序** MUST 进入对应未交付占位页（MAY 使用独立分包），**H5** MAY 使用 toast 或占位路由（效果等价即可）；MUST NOT 置灰或隐藏这些入口，也不得声称上述能力已交付。
- **FR-010**: 本切片 MUST NOT 改变 PC 预算页既有主流程；PC 仍可完整管理预算。
- **FR-011**: 交付时 MUST 同步更新 `docs/用户手册.md` 中关于「小程序 / H5 不能编辑预算、预算仅 PC」的表述，改为与本规格一致，并区分仍仅 PC 的能力（如类型配置、概览分摊等）；同时 MUST 修订 `.specify/memory/constitution.md` 原则 II，写明预算可在 PC、mobile-h5、微信小程序管理，概览/计划/类型配置/家庭资产仍以 PC 为准，并按治理规则 bump 版本。

### Key Entities

- **预算条目**：隶属于某一账本与某一自然年；关联一个支出类型与一个预算金额；花费为派生值（该年该类型已发生支出合计），不是用户手填。
- **支出类型**：账本内配置的支出分类；隐藏类型不可用于新增；与预算一对一年最多一条。
- **账本**：预算数据按账本隔离；仅该账本成员可读写。

### 不改动的现有行为

- 记账增改删、归属人规则、报销/支付方式在移动端的既有限制保持不变。
- 预算仍不拦截超支记账。
- PC 概览、计划、家庭资产、类型配置、导出与 AI 批量解析的职责边界不变（本切片不把它们搬到移动端）。
- 小程序与 H5 既有的登录/绑定/邀请差异保持不变。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在有预算数据的账本中，用户从进入账本到看清某类型预算与花费进度，可在 30 秒内完成（不含网络异常）。
- **SC-002**: 用户可在微信小程序与移动端 H5 上分别独立完成「新增 → 编辑 → 删除」一条当年预算，全程无需打开 PC；两端验收用例任务完成率均达到 100%。
- **SC-003**: 同一账本同一自然年，移动端展示的预算金额、花费与 PC 预算页对比，抽样验收一致率 100%。
- **SC-004**: 从预算卡片下钻进入搜索页后，无需再点「搜索」即可看到结果或空态；预填条件与自动搜索结果在测试数据下正确率 100%（仅含该支出类型且日期落在当前自然年）。
- **SC-005**: 用户手册更新后，不再出现「小程序/H5 不能管理预算」的过时说明；手册与实际入口一致。

## Assumptions

- 后端已具备与 PC 预算共用的查询与增删改能力；本切片以复用既有预算契约为主，不发明第二套预算语义。
- 目标端为**微信小程序与移动端 H5**，且两端均完成后本切片才算交付；PC 不作为本切片改造对象。
- 移动端预算页默认只管理**当前自然年**，与原型一致；若未来要跨年切换，另开规格。
- 「年度支出」汇总口径与 PC 预算页一致（当年已发生支出之和）；卡片「花费」为该类型当年支出合计。
- 账本内底部五入口中，本切片只要求「预算」可用；概览/计划/资产可后续规格交付。
- 本规格构成对宪章「预算仅在电脑操作」及用户手册相应表述的**有意更新**；实现前后须改手册，避免文档与产品漂移。
- 移动端预算的读写权限与 PC 一致：账本成员均可查看与增删改，页面不按「创建者」再细分（与用户手册既有口径对齐）。
