# Feature Specification: 个人信息与账本成员进出

**Feature Branch**: `014-profile-bill-members`

**Created**: 2026-11-04

**Status**: Draft

**Input**: User description: "需要支持用户修改个人信息，非账本创建者需要支持退出账本，账本创建者需要可以移除账本成员。"

## Background

当前用户手册写明：电脑端头像菜单只能「加入账本」「退出登录」，**不提供修改昵称**；账本列表仅创建者可见分享/设置/删除，加入者没有「退出账本」入口；也没有「移除成员」的产品路径。后端虽已有退出/移出相关接口雏形，但前端未接，且移出侧权限与成员匹配不完整。本规格补齐「改个人信息 / 非创建者退出 / 创建者移除成员」三条用户能力，并同步手册。

## User Scenarios & Testing *(mandatory)*

范围：**后端 API + PC + 微信小程序 + mobile-h5** 完整交付：个人信息（昵称 / 改密 / 头像）、非创建者退出账本、创建者移除成员。**宪章例外**：宪章默认禁止把新功能放进 H5，用户明确要求三端含 H5（含账本成员能力，t56u），本规格按用户指令在既有 mobile-h5/ 落地。

### User Story 1 - 修改个人信息（昵称 / 密码 / 头像） (Priority: P1)

已登录用户在同一「修改个人信息」入口可改昵称、改登录密码、上传头像。PC、微信小程序、mobile-h5「我的」页三端均提供同等入口体验。昵称保存后本地会话立刻刷新，且各账本成员显示名同步；头像上传后三端展示新头像；改密须校验旧密码，成功后清除会话并要求重新登录。

**Why this priority**: 用户明确要求昵称之外还要改密与头像，且三端都要。

**Independent Test**: 改昵称后仍可进原账本；上传头像后刷新仍显示；旧密码错误拒绝改密；改密成功后需重新登录。

**Acceptance Scenarios**:

1. **Given** 已登录用户，**When** 在 PC 头像菜单进入修改个人信息并提交合法新昵称，**Then** 保存成功，弹层关闭，立刻显示新昵称。
2. **Given** 用户已加入至少一个账本，**When** 昵称修改成功，**Then** 成员名单中自己为新昵称，且不会丢账本。
3. **Given** 提交空昵称或非法昵称，**When** 保存，**Then** 拒绝并提示，原昵称不变。
4. **Given** 小程序或 H5 已登录，**When** 在「我的」保存昵称，**Then** 页面与本地会话同步。
5. **Given** 已登录用户，**When** 选择图片上传头像，**Then** 保存成功并刷新本地用户信息中的头像展示。
6. **Given** 已登录用户提交正确旧密码与合规新密码，**When** 改密成功，**Then** 服务端清除会话，客户端退出到登录页。
7. **Given** 旧密码错误或新密码强度不合规，**When** 提交改密，**Then** 拒绝且原密码不变、会话保持。

---

### User Story 2 - 非创建者退出账本 (Priority: P1)

非创建者在账本列表对自己加入的账本执行「退出」。确认后自己不再出现在该账本成员中，列表中不再看到该账本；账本本身与其他成员的数据保留。创建者看不到「退出」，尝试退出会被拒绝并提示应使用删除账本等既有能力（本规格不新增解散/转让流程）。

**Why this priority**: 加入者目前无法离开，是明确缺口。

**Independent Test**: 用非创建者账号加入账本后退出，列表消失；创建者账号打开该账本，成员少一人且账本仍在。

**Acceptance Scenarios**:

1. **Given** 用户是某账本成员但非创建者，**When** 在 PC 账本卡片确认退出，**Then** 提示成功，列表不再含该账本。
2. **Given** 用户是账本创建者，**When** 查看账本卡片操作，**Then** 不提供退出入口；若绕过界面直接请求退出，**Then** 被拒绝并得到明确提示。
3. **Given** 小程序或 H5 账本列表中某账本非本人创建，**When** 对该账本左滑退出并确认，**Then** 列表刷新后不再显示该账本。

---

### User Story 3 - 创建者移除账本成员 (Priority: P1)

账本创建者可查看当前账本成员，并将非创建者成员移出。被移出者之后不能再进入该账本；其历史记账记录仍保留在账本中（记账人不可改的既有规则不变）。创建者不能移除自己，也不能把「创建者」身份通过移除转给他人。非创建者不能移除任何人。

**Why this priority**: 与退出对称的管理能力，用户明确要求。

**Independent Test**: 创建者移出一名成员后，被移出账号列表中无该账本；创建者再看成员名单已无此人。

**Acceptance Scenarios**:

1. **Given** 当前用户是账本创建者且账本有其他成员，**When** 在 PC / 小程序 / H5 打开成员管理并确认移除某成员，**Then** 提示成功，成员名单不再含该用户。
2. **Given** 创建者尝试移除自己或「创建者」对应账号，**When** 提交，**Then** 被拒绝并提示。
3. **Given** 非创建者，**When** 尝试移除他人，**Then** 被拒绝；三端均不对其展示移除入口。
4. **Given** 被移出用户，**When** 再打开该账本，**Then** 无法进入（沿用现有无权限/找不到提示）。

---

### Edge Cases

- 昵称改成与另一用户相同：允许（昵称非唯一登录名）；成员展示可能重名，以用户标识区分操作对象。
- 用户改昵称时，历史记账上的归属人/记账人**显示名快照**不强制回写；新产生的记录使用新昵称。
- 退出或移除后，若该用户是当前 PC 正在查看的账本，应回到账本列表并清空该账本上下文。
- 账本仅剩创建者一人时，成员管理中无可移除对象。
- 重复退出/重复移除：返回友好错误（未加入/找不到），不造成服务异常。
- 忘记密码 / 邮箱重置不在本规格；改密必须提供正确旧密码。
- 头像仅支持常见图片（jpeg/png/gif/webp），单张不超过 10MB；复用现有 OSS 私有桶与签名查看模式。
- 头像预览：三端个人信息入口须展示当前头像；选图后、保存/上传完成前须能预览新图（t52u：原「徐兰」为「预览」笔误）。
- 改密成功后踢登录（清空 session，客户端清本地会话）；仅改昵称/头像不踢登录。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 已登录用户 MUST 能修改本人昵称；昵称规则：trim 后 1～20，字符集中文/英文/数字/下划线。
- **FR-002**: 昵称保存成功后，系统 MUST 更新该用户在所有账本成员关系中的显示名，保证其仍能进入原账本。
- **FR-003**: 昵称/头像保存成功后，PC、小程序、mobile-h5 本地会话中的用户展示信息 MUST 刷新，无需重新登录。
- **FR-004**: 非账本创建者 MUST 能退出自己已加入的账本；退出后自己与该账本的成员关系解除，账本数据保留。
- **FR-005**: 账本创建者 MUST NOT 通过「退出账本」离开；系统须拒绝并提示（解散仅能走既有「删除账本」，本规格不新增转让）。
- **FR-006**: 账本创建者 MUST 能将其他非创建者成员移出账本；被移出后成员关系解除。
- **FR-007**: 系统 MUST 拒绝：非创建者移除他人、创建者移除自己、移除账本创建者、移除不存在或不在账本中的用户。
- **FR-008**: PC / 小程序 / mobile-h5 MUST 提供同一入口体验下的改昵称、改密、换头像；三端 MUST 均提供非创建者「退出账本」与创建者「移除成员」可用 UI（复用既有 `POST /bill/quit`）。
- **FR-009**: 用户手册 MUST 更新个人信息（昵称/密码/头像）与退出/移除说明，覆盖三端。
- **FR-010**: 已登录用户 MUST 能修改登录密码：校验旧密码；新密码强度与注册一致；使用现有 genPassword 哈希；成功后清除服务端 session，客户端退出登录。
- **FR-011**: 已登录用户 MUST 能上传头像：复用现有 OSS 上传与签名查看能力；三端可选图上传并展示；成功后刷新本地用户信息。
- **FR-012**: 账本转让、忘记密码重置不在本规格。

### Key Entities

- **用户资料**：登录账号下的显示昵称、头像、密码哈希；登录用户名不在此功能修改。
- **账本成员关系**：用户与某账本的加入关系及在该账本内的显示名；创建者标识在账本上，不因退出/移除而自动转移。
- **账本**：创建者可删除整本；成员退出或被移除不影响其他成员与历史明细的存续。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可在 1 分钟内完成昵称或头像修改并在界面看到更新。
- **SC-002**: 非创建者可在 1 分钟内完成退出账本，且创建者侧成员数立即少 1。
- **SC-003**: 创建者可在 2 分钟内完成一次成员移除，被移出用户无法再进入该账本。
- **SC-004**: 对创建者退出、移除自己/创建者、非创建者移除他人三类越权操作，100% 被拒绝且有可读提示。
- **SC-005**: 改昵称后，用户仍能进入改名前已加入的全部账本（无「丢账本」回归）。
- **SC-006**: 改密成功后，原会话无法继续使用（须重新登录）；旧密码错误时 100% 拒绝。

## Assumptions

- 不改登录用户名；改密需旧密码；头像复用记账图片的 OSS/签名方案，对象键存 users.avatar_url。
- 退出/移除只解除成员关系，不删除该用户历史记账，不重算历史归属快照。
- 后端已有退出/移出接口意图时，以补齐权限与匹配正确性为先，保持对外路径兼容。
- 退出/移除 UI 三端对齐（t56u）：PC 账本卡片；小程序/H5 列表左滑退出 + 明细页「成员」管理。
- 宪章 vs 用户：宪章写明不再把新功能放进 mobile-h5；用户 t50u 明确要求三端。以用户为准在 mobile-h5/ 落地本功能，并在 plan 中记录例外。
- 昵称校验：trim 后 1～20，中文/字母/数字/下划线。
