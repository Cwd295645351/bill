# Data Model: 小程序编辑记账回填原日期

本次不新增实体，不改字段，不改表。下面只描述编辑日期时已经存在的数据，以及允许的变化。

## 记账明细

一笔收入或支出。编辑日期只读取、并在用户保存后写回其中的日期。

| 字段 | 含义 | 本次规则 |
|------|------|----------|
| id | 这笔账的标识 | 编辑保存时原样带回。不改。 |
| billId | 所属账本 | 不改。 |
| userId | 记账人 | 不可改。只有与当前用户相同的记录能进入编辑。 |
| date | 自然日，毫秒时间戳 | 打开编辑时格式化为日历日显示。用户未改日期就保存时，写回的自然日必须与打开前相同。 |
| money | 金额 | 继续回填原值。本次不改规则。 |
| type | 支出或收入 | 继续回填原值。 |
| costTypeId / incomesTypeId | 分类 | 继续回填原值。 |
| belongUserId | 归属人 | 继续回填原值。可为空，表示「全部」。 |
| remark | 内容 | 继续回填原值。 |
| reimbursement | 报销进度 | 编辑时保持原值，本次不改。 |

关系：一条明细只属于一个账本。同一自然日可以有多笔，编辑只影响当前这一笔。

## 编辑表单上的日期

表单不单独持久化。它是记账明细 `date` 的一种展示。

| 字段 | 含义 | 校验 |
|------|------|------|
| date | 选择器上的日历日，文本 `YYYY-MM-DD` | 编辑打开后必须等于明细 `date` 的日历日。不是这个格式的文本不能当作原日期。 |
| recordId | 正在编辑的明细 id | 有值表示编辑。编辑时禁止在日期为空时改用今天。 |
| mode | `add` 或 `edit` | `add` 且日期尚空时，默认今天。`edit` 不使用这个默认值。 |

来源：账本流水和搜索结果里的同一条明细。两条入口都不改明细内容，只把这条明细交给编辑页。

## 状态变化

```text
未打开
  → 打开编辑：表单日期 = 明细原自然日
  → 用户改了日期选择器：表单日期 = 用户选的自然日
  → 保存成功：明细日期 = 表单上的自然日（当天 00:00 的毫秒时间戳）
  → 保存失败，或未保存离开：明细日期保持打开前的值
```

新增是另一条路径：打开时日期为空则填今天；保存时用用户最终留下的那一天。不从编辑状态转成新增。

## 明确不变的数据

- 搜索筛选的开始日、结束日。
- 预算年度、计划日期。
- 电脑网页端和手机网页端已经保存的明细。
