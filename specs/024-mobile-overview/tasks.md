## 阶段 3：用户故事 1 - 按月或按年查看收支与结算（优先级：P1）🎯 MVP

**目标**: 两端打开概览即看到当前自然月的四个汇总数、成员收入和结算建议，并能改月、改年、单独改一端日期

**独立测试**: 打开已有收支的账本概览，确认开始和结束在同一行且中间为「至」。只改一端、切换上一月、直接选另一个月，再切到年并选另一个年份。验收区间、四个汇总数、收入行和结算建议，不必先看支出结构

### 用户故事 1 的实现

- [x] T009 [P] [US1] 在 `mobile-h5/src/api/overview.ts` 实现 `GET /overview/mobile` 的调用，查询参数为 `billId`、`beginDate`、`endDate`（`YYYY-MM-DD`）
- [x] T010 [P] [US1] 在 `miniapp/miniprogram/apis/index.ts` 实现同一个主查询调用，参数与 H5 相同
- [x] T011 [US1] 在 `mobile-h5/src/router/index.ts` 增加 `/bill/:id/overview`。在 `mobile-h5/src/components/BookTabBar.vue` 把「概览」从只提示改为进入该路由；「资产」仍 toast「请到电脑端查看或管理」（依赖 T009）
- [x] T012 [US1] 在 `mobile-h5/src/views/overview/OverviewView.vue` 做时间与收支卡片。默认维度「月」，两端为当前自然月第一天和最后一天。月有「上一月」「下一月」，年有「上一年」「下一年」。点中间年月可先改年再选月，点中间年份只能选 `minYear` 到 `maxYear`。切换维度、翻页或点选后，两端重置为该自然月或自然年的首尾日并立即刷新。开始和结束在同一行，中间为「至」。只改一端时另一端不变，月份或年份标题不变。开始晚于结束时提示「开始时间不能晚于结束时间」并恢复原值，不发请求。展示总支出、总投资、总消费、总收入。有收入的成员一行，文案为「成员名收入」加金额，不得显示「（甲）甲收入」。没有收入时说明这段时间没有收入。结算建议原样展示 `lines`。切换账本后回到当前自然月和「月」。未来区间按空数据处理，不得报错。成员名很长时收入行和结算句仍须完整可读。页面不得出现数量、归属、「计算」、近三年或近五年（依赖 T011）
- [x] T013 [US1] 用 `miniapp/miniprogram/packageOverview/pages/overview/index.ts`、`index.wxml`、`index.wxss`、`index.json` 替换占位页，交互和文案与 T012 相同。标题须体现概览。进入页时继续调用 `miniapp/miniprogram/utils/auth` 的 `guardPage`，未登录不得查看。底部五个入口仍在，且「概览」为当前项（依赖 T010）

**检查点**: 两端都能在约 10 秒内看到当前月四个汇总数和结算建议，且不用先填日期。同一年的汇总数和结算金额与电脑端同一区间一致

## 阶段 4：用户故事 2 - 查看支出结构并下钻明细（优先级：P1）

**目标**: 同一区间内按「全部」或成员看环形占比和分类列表，点分类看到原始消费明细

**独立测试**: 打开已有多种支出的账本概览，切换成员，核对列表与环形图，再点开一个分类。不必修改概览规则

### 用户故事 2 的实现

- [x] T014 [US2] 在 `server/modules/overview/mobile-view.ts` 与 `server/modules/overview/router.ts` 实现 `GET /overview/mobile/records`。参数为 `billId`、`beginDate`、`endDate`、`costTypeId`，可选 `memberId`。日期与成员校验同主接口。不传 `memberId` 表示「全部」。传入时只保留归属该成员、归属「全部」、或该成员参与的多人支出。每条含 `date`（`YYYY-MM-DD`）、`payerName`、`belongName`、记账原金额 `money`、可空 `remark`。按日期从新到旧，同一天按 id 从新到旧。没有记录时 `total` 为 0 且 `records` 为空数组，仍然成功。不得返回分摊份额（依赖 T007）
- [x] T015 [US2] 在 `server/modules/overview/mobile-view.ts` 的主响应中填充 `categories`。「全部」的 `money` 是记账原金额；成员的 `money` 是各自然年应承担份额之和。`count` 是可点开的原始记账笔数，条件与 T014 相同，且 `total` 必须等于对应分类的 `count`。金额为 0 的分类不出现。按金额从高到低，金额相同按名称中文排序。`percent` 是不带百分号的两位小数：除最后一项外按金额占比四舍五入，最后一项等于 100 减去其余占比，使该列表之和为 100.00；只有一项时为 `100.00`。`categories.all` 与每个成员的 `slices` 各自计算。只有一名当前成员时 `categories.members` 为空数组（依赖 T014）
- [x] T016 [P] [US2] 在 `mobile-h5/src/views/overview/OverviewView.vue` 增加支出结构。两名及以上成员可在「全部」和每一名当前成员间切换；只有一名时只提供「全部」。上方环形图和图例，下方分类行。行内有分类名、占比、笔数、金额和进度。进度宽度等于占比，最多 100%。图例与列表使用接口返回的同一组百分比。点环形图中的一类或点同一行，打开页内明细，条数等于该行笔数，金额是记账原金额。没有支出时显示暂无，不留空白环形图。分类名和金额很长时必须完整可读，不得截断到无法辨认。不引入 echarts，不复制预算分包的画布组件（依赖 T015）
- [x] T017 [P] [US2] 在 `miniapp/miniprogram/packageOverview/pages/overview/index.ts`、`index.wxml`、`index.wxss` 实现与 T016 相同的支出结构和明细。分类名和金额很长时必须完整可读，不得截断到无法辨认。明细不跳搜索页或记账列表（依赖 T015）

**检查点**: 环形图与列表金额一致。成员明细不含与该成员无关的记录。两端分类金额和笔数一致

- **准备（阶段 1）**: 无依赖，可立即开始

## 实施策略

### 先做 MVP（仅用户故事 1）

1. 完成阶段 1：准备
2. 完成阶段 2：基础能力，并用电脑端跨年区间确认结算已按年合并
3. 完成阶段 3：用户故事 1
4. **停下来验收**：两端当前月汇总数、收入和结算建议
5. 通过后再做支出结构和文档

### 增量交付

1. 准备 + 按年结算 → 电脑端跨年结果先正确
2. 用户故事 1 → 两端能看当前月收支和结算
3. 用户故事 2 → 补上结构、占比和明细
4. 用户故事 3 → 确认没有临时试算，配置只读
5. 用户故事 4 → 两端对账，且不改电脑端页面、不打开资产
6. 手册与宪章 → 才能按 SC-005 宣称交付

### 多人并行策略

1. 共同完成阶段 1 和阶段 2
2. 之后一人做 H5 页面，一人做小程序页面
3. 服务端的分类和明细由一人先完成，两端再同时接支出结构
4. 文档两人可同时改手册和宪章
