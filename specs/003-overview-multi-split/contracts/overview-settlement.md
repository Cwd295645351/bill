# Contract: 概览结算

电脑端查询分账时使用。手机网页和小程序不调用。现有接口保持原样：

- `GET /api/v1/overview/balance`：总支出、总投资、总收入、按人加总的明细。字段不增删，含义不变。
- `GET /api/v1/overview/threeYearCost`：近三年支出。不改。

登录方式与其它 `/api/v1` 接口相同。未登录仍按现有方式拒绝。

## POST /api/v1/overview/settlement

### 请求

```json
{
  "billId": "账本 id",
  "beginDate": 1704067200000,
  "endDate": 1735689599999,
  "quantityInputs": [
    { "ruleId": "数量规则 id", "quantity": 10, "belongUserId": "成员用户 id" }
  ]
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| billId | 是 | 当前账本 |
| beginDate / endDate | 是 | 与现有概览汇总同一套时间解释 |
| quantityInputs | 否 | 不传或空数组表示所有数量规则的数量为 0 |
| quantity | 否 | 缺省为 0。必须大于等于 0 |
| belongUserId | 数量大于 0 时必填 | 必须是当前成员 |
| ruleId | 该条存在时必填 | 必须是本账本已启用的数量规则 |

浏览器不得提交单价。指定支出类型规则不在请求里，由服务端按账本配置计算。

### 成功响应

`data` 形状如下。金额除说明为整数分的字段外，都是保留两位小数的数。

```json
{
  "members": [
    {
      "userId": "成员用户 id",
      "name": "甲",
      "effectiveIncome": 6000,
      "weight": 6000,
      "paid": 15000,
      "borne": 6000,
      "net": 9000
    }
  ],
  "lines": ["乙 → 甲 转 9000.00 元"],
  "transfers": [
    { "fromUserId": "乙的 id", "fromName": "乙", "toUserId": "甲的 id", "toName": "甲", "amount": 9000 }
  ],
  "pies": {
    "all": [{ "costTypeId": "1001", "name": "餐饮买菜", "money": 300 }],
    "members": [
      {
        "userId": "甲的 id",
        "name": "甲",
        "slices": [{ "costTypeId": "1001", "name": "餐饮买菜", "money": 100 }]
      }
    ]
  }
}
```

| 字段 | 说明 |
|------|------|
| members | 仅当前成员，按 `bill_users.id` 升序。`weight` 已包含「全体为 0 则改为均分」之后的本次权重 |
| lines | 直接显示的文案。两人且没有局外人时最多一行：「双方结清，无需转账」或「甲 → 乙 转 N 元」。多人用多行，结清时为「各方结清，无需转账」。一名成员且没有非零净额时为「无需分账」 |
| transfers | 与 `lines` 中的转账一致，不含 0 元。局外人的 `userId` 使用记账上的 id，姓名使用记账上的姓名 |
| pies.all | 未按人拆分的全部支出。一名成员时 `pies.members` 为空数组 |
| pies.members | 每个当前成员一张。不含归属其他人的支出。公共部分来自区间合计只分一次的结果，按支出类型汇总。顺序与 `members` 相同 |

响应不包含 `publicAllocations`。明细里的金额由记账列表提供，是记账原金额。

总支出、总投资、总消费、总收入仍只从 `GET /balance` 读取。本接口不返回这些汇总数。

### 失败

沿用现有响应包装：成功 `retCode === 0`，失败为错误信息。至少覆盖：

| 情况 | 说明 |
|------|------|
| 缺少账本或起止时间 | 与现有汇总接口一样拒绝 |
| 当前用户不是该账本成员 | 拒绝，不返回任何金额 |
| 数量为负、规则不属于本账本、规则未启用、或不是数量规则 | 拒绝，并说明哪一条不能用 |
| 数量大于 0 但归属人不是当前成员 | 拒绝 |

失败时电脑端保持上一次成功的结算和建议，不把画面清空成 0。

### 不在本接口做的事

- 不写记账，不改规则，不改成员。
- 不返回近三年趋势。
- 不按报销进度剔除或改金额。
- 不下发可以改单价的字段。
