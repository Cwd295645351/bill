# Feature Specification: 移动端计划模块

**Feature Branch**: `019-mobile-plan`

**Created**: 2026-11-10

**Status**: Draft

**Input**: User description: "根据原型 `prototypes/miniapp.html` 实现该原型中的计划模块，包含移动端和微信小程序"

## 背景与边界

当前产品中，计划（待购 / 待办备忘）的查看与增删改仅在 PC 端完整提供；微信小程序已有计划分包占位页（提示请到电脑端），移动端 H5 账本底部点「计划」仅 toast 提示，用户手册亦写明计划请到电脑操作。

`prototypes/miniapp.html` 已把计划做成账本内一级能力：进入账本后底部可切换「记账 / 概览 / 预算 / 计划 / 资产」。计划页顶部有「不会自动变成记账」的说明；列表按高 / 中 / 低三档优先级分组展示卡片（标题、内容、编辑与删除）；底部可「新增计划」；表单含标题、内容与优先级（新建默认高，与 PC 一致），保存前须填齐标题与内容；删除需二次确认。

本规格交付**移动端（微信小程序 + 移动端 H5）计划模块**，交互与信息架构以该原型为准，业务口径与现有 PC 计划保持一致。本切片**不包含**概览、家庭资产（含资产下的「养老计划」）的移动端实现，也不改造 PC 计划页主流程。

## Clarifications

### Session 2026-11-10

- Q: 用户在手机上点「新增计划」时，优先级应默认选中哪一档？ → A: 默认「高」（与当前 PC 新增表单一致；本切片不改 PC）
- Q: 同一优先级下有多条计划时，卡片应按什么顺序排列？ → A: 与 PC 一致：同档内按服务端返回顺序展示，移动端不另做排序
- Q: 计划在 H5 交付后，账本底部点「概览」或「资产」时，H5 应如何表现？ → A: H5 继续 toast 提示「请到电脑端查看或管理」；小程序仍进入未交付占位页
- Q: 标题与内容除「不能为空」外，是否还要设移动端专属的字数上限？ → A: 不设移动端专属上限；仅校验非空（与 PC 一致）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在手机上按优先级查看计划 (Priority: P1)

已登录且至少加入一个账本的用户，进入某个账本后切换到「计划」，看到「计划只是想买或待办、不会自动变成记账」的提示，以及按高 / 中 / 低优先级分组的计划卡片，用于随时翻看待办与想买事项。

**Why this priority**: 没有可读的分组列表，移动端计划就没有日常价值；这是最小可用交付。

**Independent Test**: 在已有计划数据的账本中打开计划页，即可独立验收分组、卡片字段与提示文案，无需先完成新增流程。

**Acceptance Scenarios**:

1. **Given** 用户已进入某账本，**When** 点底部「计划」，**Then** 进入计划页，标题为「计划」，底部仍保留账本内五个入口（记账 / 概览 / 预算 / 计划 / 资产）且「计划」高亮。
2. **Given** 用户在账本内底部导航，**When** 点「概览」或「资产」，**Then** 入口保持可点外观（不置灰、不隐藏）；**小程序**进入对应未交付占位页并提示请到电脑端查看或管理（占位页不得展示已交付业务内容）；**H5** 停留在当前页并以 toast 提示请到电脑端查看或管理（本切片不为 H5 新建概览/资产占位页）。
3. **Given** 打开计划页，**When** 查看页顶说明，**Then** 明确告知计划不会自动变成记账，买完后需到记账里补支出。
4. **Given** 该账本已有若干计划分属不同优先级，**When** 打开计划页，**Then** 固定展示「高优先级 / 中优先级 / 低优先级」三档分区（高红、中橙、低绿），各档下列出对应卡片；卡片展示标题与内容；同一优先级内的相对顺序与 PC / 服务端返回顺序一致。
5. **Given** 某一优先级下没有计划，**When** 查看该档，**Then** 该档显示「这一档还没有」之类空态，其它档照常展示。
6. **Given** 该账本没有任何计划，**When** 打开计划页，**Then** 三档分区仍在，每档为空态，仍可看到底部「新增计划」。

---

### User Story 2 - 新增、编辑、删除计划 (Priority: P1)

账本成员在手机上新增一条计划、改标题 / 内容 / 优先级，或删除不再需要的计划；删除不可恢复，且不会影响任何记账明细。

**Why this priority**: 原型把移动端计划做成可管理能力；若只能看不能改，仍要回 PC，无法兑现原型目标。

**Independent Test**: 从空计划账本新增一条、再编辑字段、再删除，可完整验收，不必依赖其它模块。

**Acceptance Scenarios**:

1. **Given** 用户在计划页，**When** 点「新增计划」，**Then** 打开表单：可填标题、内容；可选手动优先级「高 / 中 / 低」；新建时默认选中「高」（与当前 PC 新增一致）。
2. **Given** 新增或编辑表单中标题或内容为空（或仅空白），**When** 点保存，**Then** 不保存并给出明确提示（如请填写标题和内容）；本切片不因字数过长而单独拒收（无移动端专属字数上限）。
3. **Given** 用户填写了非空标题与内容并选了优先级，**When** 保存成功，**Then** 关闭表单，该条出现在对应优先级分区。
4. **Given** 已有计划卡片，**When** 点「编辑」，**Then** 表单预填当前标题、内容、优先级，均可修改；保存后列表与分区位置随之更新（若改了优先级则换档）。
5. **Given** 已有计划卡片，**When** 点「删除」并确认，**Then** 该条从列表消失且不可恢复；取消确认则不做删除。
6. **Given** 用户删除或修改计划，**When** 查看该账本记账明细，**Then** 既有记账不受影响。

---

### User Story 3 - 小程序与 H5 能力对齐 (Priority: P2)

同一账本的计划数据在微信小程序与移动端 H5 均可查看与管理，两端信息结构与操作结果一致；两端仅在登录 / 邀请等既有差异上不同，计划业务本身无端侧特例。

**Why this priority**: 原型明确「同一份稿同时覆盖小程序与 H5」；本切片以两端都可用为交付完成条件。

**Independent Test**: 分别在小程序与 H5 对同一账本执行查看与增删改，对比结果与 PC 计划一致；任一端缺失则本切片未完成。

**Acceptance Scenarios**:

1. **Given** 用户在 PC 为某账本新增一条计划，**When** 在小程序与 H5 分别打开该账本计划页，**Then** 两端都能看到同一条计划，且落在同一优先级分区。
2. **Given** 用户在 H5（或小程序）修改或删除一条计划，**When** 在另一移动端或 PC 刷新计划，**Then** 变更已生效。
3. **Given** 用户使用小程序或 H5，**When** 使用计划页，**Then** 不出现仅某一端才有的计划业务字段或互斥规则。
4. **Given** 进行本切片验收，**When** 仅有一端完成计划模块，**Then** 不得判定本切片交付完成。

---

### Edge Cases

- 标题、内容仅含空格时视为未填写，不可保存；除非空外不设移动端专属字数上限（与 PC 一致）。
- 优先级仅允许高 / 中 / 低三档；非法或缺失优先级不得保存。
- 删除计划需二次确认；误触取消不得删除；删除后不可恢复。
- 计划与记账无自动联动：保存或删除计划都不会新增、修改或删除任何记账。
- 用户不是该账本成员、或未登录时，不能查看或改该账本计划。
- 某一优先级为空时，该档显示档内空态，不得整页误显示为「无计划」而隐藏其它档。
- 列表口径与 PC 一致：不展示已逻辑删除或已被标记为「已购」而不再出现在 PC 列表中的条目（移动端本切片不新增「已购」操作入口）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 微信小程序与移动端 H5 MUST 均在账本内提供可用的「计划」入口（账本内底部导航之一），进入后展示该账本的计划管理页；本切片交付完成的前提是两端计划模块均可用。
- **FR-002**: 计划页 MUST 展示顶部说明：计划只是想买或待办，不会自动变成记账；买完后需再到记账里补一条支出。
- **FR-003**: 计划页 MUST 按「高优先级 / 中优先级 / 低优先级」三档固定分区展示（视觉上高红、中橙、低绿）；每条计划卡片 MUST 展示标题与内容；同一优先级内 MUST 按服务端返回顺序展示，MUST NOT 在移动端另行按时间或标题重排。卡片上的「编辑」「删除」操作入口由 **FR-006 / FR-007** 约束，可在增删改故事中交付，不要求「仅查看」MVP 单独先上可操作按钮。
- **FR-004**: 某一优先级下无条目时，该档 MUST 显示档内空态（如「这一档还没有」）；整本无计划时仍 MUST 保留三档分区与「新增计划」入口。
- **FR-005**: 账本成员 MUST 能新增计划：填写非空标题与内容，选择优先级（新建默认「高」，与当前 PC 新增表单一致）并保存；MUST NOT 增设仅适用于移动端的标题 / 内容字数上限。
- **FR-006**: 账本成员 MUST 能编辑已有计划的标题、内容与优先级；保存后列表与分区归属 MUST 与最新优先级一致；编辑校验规则与新增相同（非空、无移动端专属字数上限）。
- **FR-007**: 账本成员 MUST 能在确认后删除计划；删除 MUST NOT 影响已有记账明细，且删除后不可恢复。
- **FR-008**: 移动端计划的数据口径（账本隔离、标题 / 内容 / 优先级语义、列表可见范围、同档顺序）MUST 与现有 PC 计划一致，使同一账本在多端看到的计划一致。
- **FR-009**: 本切片 MUST NOT 实现移动端概览、家庭资产（含资产内「养老计划」）的业务能力；账本底部仍 MUST 展示五个入口；「概览 / 资产」被点击时 MUST 提示请到电脑端查看或管理——**小程序** MUST 进入对应未交付占位页（MAY 使用独立分包），**H5** MUST 以 toast 提示且 MUST NOT 为本切片新建概览/资产占位页；MUST NOT 置灰或隐藏这些入口，也不得声称上述能力已交付。
- **FR-010**: 本切片 MUST NOT 改变 PC 计划页既有主流程；PC 仍可完整管理计划。本切片 MUST NOT 在移动端新增「已购」标记入口（与当前 PC 计划页用户可见能力对齐）。
- **FR-011**: 交付时 MUST 同步更新 `docs/用户手册.md` 中关于「小程序 / H5 不能管理计划、计划仅 PC」的表述，改为与本规格一致，并区分仍仅 PC 的能力（如类型配置、概览分摊、家庭资产等）。`.specify/memory/constitution.md` 原则 II 须写明计划可在 PC、mobile-h5、微信小程序管理（概览 / 类型配置 / 家庭资产仍以 PC 为准）；若交付前已按治理 bump 至含该表述的版本，则宪章部分视为已满足，仍以手册更新为交付硬门禁。

### Key Entities

- **计划条目**：隶属于某一账本；包含标题、内容与优先级（高 / 中 / 低）；用于备忘待购或待办，不直接产生记账。
- **优先级档**：展示与排序用的三档分组；同一账本内多条计划可同档。
- **账本**：计划数据按账本隔离；仅该账本成员可读写。

### 不改动的现有行为

- 记账增改删、归属人规则、报销 / 支付方式在移动端的既有限制保持不变。
- 计划仍不自动生成或修改记账。
- PC 概览、家庭资产、类型配置、导出与 AI 批量解析的职责边界不变（本切片不把它们搬到移动端）。
- 预算模块既有移动端能力保持不变。
- 小程序与 H5 既有的登录 / 绑定 / 邀请差异保持不变。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在有计划数据的账本中，用户从进入账本到看清某条计划所属优先级与内容，可在 30 秒内完成（不含网络异常）。
- **SC-002**: 用户可在微信小程序与移动端 H5 上分别独立完成「新增 → 编辑 → 删除」一条计划，全程无需打开 PC；两端验收用例任务完成率均达到 100%。
- **SC-003**: 同一账本，移动端展示的计划标题、内容、优先级分区及同档内相对顺序与 PC 计划页对比，抽样验收一致率 100%。
- **SC-004**: 未填标题或内容时保存失败率 100%（不得静默成功）；删除取消后计划仍在列表中的正确率 100%。
- **SC-005**: 用户手册更新后，不再出现「小程序 / H5 不能管理计划」的过时说明；手册与实际入口一致。

## Assumptions

- 后端已具备与 PC 计划共用的查询与增删改能力；本切片以复用既有计划契约为主，不发明第二套计划语义。
- 目标端为**微信小程序与移动端 H5**，且两端均完成后本切片才算交付；PC 不作为本切片改造对象。
- 移动端计划页的信息架构与交互以 `prototypes/miniapp.html` 的计划屏为准（三档竖向分组、底部新增、表单弹层、删除确认）；PC 的三列横排仅为桌面布局差异，不要求移动端复刻三列并排。
- 账本内底部五入口中，本切片要求「计划」可用；「概览 / 资产」可后续规格交付：小程序继续占位页，H5 继续 toast（本切片不为 H5 补占位路由）。
- 「养老计划」属于家庭资产能力，不在本切片范围。
- 本规格构成对宪章「计划仅在电脑操作」及用户手册相应表述的**有意更新**；实现前后须改手册与宪章，避免文档与产品漂移。
- 移动端计划的读写权限与 PC 一致：账本成员均可查看与增删改，页面不按「创建者」再细分（与用户手册既有口径对齐）。
- 标题 / 内容字段校验与 PC 对齐：去空白后非空即可，本切片不引入移动端专属字数上限。
