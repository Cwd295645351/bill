# Quickstart: 服务端源码改为 TypeScript

验收源码语言、发布前检查，以及记账行为是否保持。不包含实现代码。数据对照 [data-model.md](./data-model.md)，对外结果对照 [contracts/behavior-parity.md](./contracts/behavior-parity.md)。

## 前提

- Node.js 18 及以上，`server/` 已执行依赖安装。
- `server/.env` 已按部署说明配好数据库口令和密钥。MySQL、Redis 可连接。
- 准备一个改写前就存在的账号和账本，记下成员人数、一笔明细的金额、记账人和归属人。
- 电脑网页或小程序能访问这套服务端。本机默认是 `http://127.0.0.1:3000`。

以下命令在 `server/` 目录执行。

## 1. 类型错误不能发布

1. 在任意业务源码里把一个明确的数字参数或返回值改成字符串，保存。
2. 执行类型检查。

期望：检查失败，输出里有该文件和出错位置。此时不要执行生产启动。

把改动还原后再次检查。期望：检查通过。不要把故意写错的类型留在仓库里。

## 2. 编译并启动

1. 执行生产编译。
2. 按更新后的部署说明启动（本地可先手动启动一次，确认后再交 PM2）。

期望：

- 编译成功后才有可运行产物。编译失败时启动步骤不会使用这次失败的结果。
- 进程监听原来的端口。PM2 进程名仍是 `bill-manage`。
- 密钥仍从 `server/.env` 读取，访问日志仍写入 `server/logs/access.log`。

另做一次反例：临时移走或清空一项必填密钥后再启动。期望：进程退出，并提示缺少该项，而不是继续对外记账。测完后恢复 `.env`。

## 3. 记账结果与改写前一致

用改写前的账号完成下面五项，电脑网页和小程序至少各抽一项登录后的操作：

1. 登录。
2. 打开对照账本。
3. 记一笔。
4. 修改自己刚记的这一笔；换一个成员操作，确认改不了。
5. 用分享码加入（可用测试账本，避免打扰正式家庭账本）。

期望：五项都成功，规则与改写前相同。对照明细的金额、记账人、归属人不变。未登录就记账时，拒绝原因与改写前一致。

## 4. 源码与说明

- `server/` 里会在进程中执行的业务和启动源码都是 TypeScript。`prettier.config.js`、`pm2.conf.json` 和环境文件除外。
- `deploy/linux.md` 与 `deploy/windows.md` 的启动步骤包含编译，并且不再把 `babel-node` 或旧的 `.js` 入口写成现行步骤。
- `frontend/`、`miniapp/` 没有为这次改写改请求或页面。`docs/用户手册.md` 的操作步骤不需要改。
