# Data Model: PC 端新增记账支持附图

**Branch**: `020-pc-add-record-images` | **Date**: 2026-11-10

本切片**不新增表、不改列**。实体与生命周期沿用 `specs/002-record-image-upload/data-model.md`，此处只写与「PC 单条新增附图 + 保存时再传」相关的约束与状态。

## 实体（复用）

### 记账明细（Transaction）

- 既有字段不变。
- PC 单条新增成功后，可关联 0～9 张可查看照片。
- AI 批量解析写入的明细本次不关联照片。

### 记账照片（TransactionImage）

| 属性 | 说明 |
|------|------|
| id | 照片 id |
| billId | 所属账本 |
| transactionId | 挂接后的记账 id；未挂接时为空 |
| uploaderUserId | 上传人（须为后续挂接时的记账人） |
| sort | 展示顺序（按提交的 `imageIds` 顺序） |
| viewable | 挂接且未随整笔删除前为可查看 |
| viewUrl | 列表接口签发的查看地址（前端只读） |

## 校验规则（新增 / 编辑挂接路径）

PC 在保存时先上传再提交 `imageIds`，服务端规则不变：

1. 数组长度 0～9；非法形状整笔失败。
2. 每张属于当前 `billId`、由当前用户上传、尚未挂到其他记账（编辑时可包含本笔原图）、仍可挂接。
3. 任一条件失败或记账写入失败：不产生该笔（新增）或原账不变（编辑）；用户侧流水不出现未完成的附图结果。
4. 新增不传 `imageIds`：行为与今天一致，新账无照片。

## 客户端临时状态（非持久化）

### PhotoDraft（PC；新增用 `addImages`，编辑用 `editImages`）

| 字段 | 说明 |
|------|------|
| id | 可选；已挂接原图才有；新选本地文件在上传成功前为空 |
| file | 可选；新选本地文件 |
| sort | 表单内顺序 |
| viewUrl | 本地 blob 预览或原图签名地址 |

状态转换（新增，`addImages: PhotoDraft[]`）：

```text
[空]
  → 选图校验通过 → [草稿含本地 file + 预览]（不调用上传）
  → 单张删除 → 从草稿移除；revoke 预览
  → 支出/收入切换 → 草稿不变
  → 取消 / 关闭 → 清空草稿；不调用上传、不挂接
  → 点保存 → 按序上传 → 提交 imageIds
       → 成功 → 清空草稿；流水可查看
       → 上传或记账失败 → 草稿与已填字段保留；流水无缺图新账
```

状态转换（编辑，`editImages: PhotoDraft[]`）：

```text
打开编辑 → 草稿 = 已挂接原图（有 id）
  → 新选文件 → 仅追加本地 file（不上传）
  → 去掉某张 → 从草稿移除
  → 取消 → 丢弃本地新文件；不上传
  → 确定 → 上传新文件 → 提交完整 imageIds
```

## 关系

- 一笔记账 0～9 张照片；一张照片最多挂一笔记账。
- 账本隔离：照片不可跨账本查看或挂接。
- 删除整笔记账后，成员不可再查看其照片（既有规则）。
- 取消路径不得写入对象存储；仅「上传已成功但随后记账提交失败」可能留下极少未挂接行（与小程序/H5 相同窗口；用户侧不可见，本切片不要求物理清扫）。
