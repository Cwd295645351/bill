# Contract: PC 单条新增附图（客户端行为）

**基础路径**: `/api/v1`  
**完整服务端契约**: 复用 [002 transaction-images](../../002-record-image-upload/contracts/transaction-images.md)，本文件只约定本切片 **PC 客户端必须遵守的调用与不调用行为**。  
**响应形状**: 仍为 `{ retCode, message, data }`；成功时新增响应 `data` 保持现有空形状，不得为了返回新 id 而改形状。

## 上传时机（本切片强制）

`POST /api/v1/transaction/image`

- `multipart/form-data`：`file` + `billId`
- **调用时机**：仅在用户点「保存 / 确定」之后、提交新增或编辑记账之前；按草稿顺序逐张上传
- **禁止**：选图变更事件里立即上传（含编辑弹窗新选文件）
- 成功：拿到 `data.id` 后拼入本次要提交的 `imageIds`
- 选图阶段：只做本地校验（jpeg/png/gif/webp；单张 ≤10MB；总数 ≤9）与本地预览；**不调用本接口**

任一张上传失败：中止后续上传与记账提交；提示用户；表单保留已填字段与本地已选图。

## 单条新增挂接（复用）

`POST /api/v1/transaction`

| 场景 | 客户端步骤 | `imageIds` |
|------|------------|------------|
| 有本地新选照片并保存 | 先上传全部新文件 → 再新增 | 显式传入本次 id 数组（按展示顺序） |
| 未选照片 | 不上传 | **不传**该字段 |
| 保存中再次点击 | 防抖 / 忽略 | 不得产生两笔相同账 |

挂接失败或新增失败：不产生记账；本次刚上传、未挂接成功的 id 对流水不可见。接受与小程序/H5 相同的极少未挂接行仅出现在「上传成功但记账失败」窗口（用户侧不可见，本切片不要求物理清扫）；**取消路径不得产生**任何上传。

## 编辑挂接（本切片调整客户端时机）

`PUT /api/v1/transaction`

| 场景 | 客户端步骤 |
|------|------------|
| 只改文字、照片未变 | 不调上传；`imageIds` 为当前仍保留的原图 id 列表（与现编辑语义一致：显式传则替换为该列表） |
| 去掉部分原图、无新文件 | 不调上传；`imageIds` 为剩余原图 id |
| 有新选本地文件 | 先上传新文件 → `imageIds` = 保留的原图 id + 新 id（按展示顺序） |
| 取消编辑 | **不调上传**；丢弃本地新选文件 |

## 明确不调用 / 不扩展

| 接口或能力 | 本切片约定 |
|------------|------------|
| `POST /api/v1/transaction/batch`（或现有批量新增） | **不传** `imageIds`；批量解析 UI 不增加照片列 |
| 列表 `POST /api/v1/transaction/list` | 继续消费可选 `images[]`；保存成功后刷新列表即可看到 |
| 小程序 / H5 上传入口 | 本切片不改其客户端代码 |

## 错误与用户可见文案（对齐既有）

| 情况 | 用户可见方向 |
|------|----------------|
| 超过 9 张 | 「最多 9 张」 |
| 单张过大 | 「单张照片不能超过 10MB」 |
| 非图片类型 | 「无法当作照片打开」 |
| 上传失败 | 「照片没有保存成功」或服务端 `message`；整笔不保存成功 |
| 整笔新增/编辑失败 | 提示失败；草稿照片与已填字段保留 |

## 文案契约（产品可见）

- 电脑端界面与用户手册不得再出现「新记一笔不能附照片」或「电脑上新记一笔不能附照片」。
- 须能表达：单条新增与编辑均可附照片；每笔最多 9 张、单张不超过 10MB；同账本可看、仅记账人可增删；AI 批量解析写入不附照片。
