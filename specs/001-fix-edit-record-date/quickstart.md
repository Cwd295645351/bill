# Quickstart: 验证小程序编辑日期回填

手工验证。小程序仓库没有测试脚本。不要为了这次修复去改接口或造数据表。

相关约定：

- 日期含义见 [data-model.md](./data-model.md)
- 打开编辑和保存时日期应是什么，见 [contracts/miniapp-edit-date.md](./contracts/miniapp-edit-date.md)

## 准备

1. 用微信开发者工具打开 `miniapp/`。若还没构建 npm，先执行「工具 → 构建 npm」。
2. 使用一个已绑定微信的账号，进入有本人记账的账本。
3. 至少准备这些本人记账（日期以流水分组标题为准）：
   - 不是今天的一天
   - 今天
   - 另一个月
   - 另一年
4. 再准备一条**别人**记的账，用来确认仍然不能编辑。

下面把「不是今天的那笔」称为样本。记下它在流水里的日期、金额和内容。

## 1. 从流水打开编辑

1. 在账本流水点样本的编辑。
2. 期望：日期格是样本的原日期，不是今天。金额、分类、归属人、内容仍是原值。
3. 不改日期，只改金额或内容，保存。
4. 期望：样本仍出现在原日期那一组。今天的分组不新增这笔。金额或内容是刚改过的值。
5. 再打开这笔编辑，把日期改成另一个自然日并保存。
6. 期望：它出现在新日期下，原日期下不再有这一笔。其它未改字段不变。
7. 打开一笔日期就是今天的本人记账。期望日期是今天。不保存，直接返回。期望该笔仍在今天。

## 2. 从搜索打开编辑

1. 搜索到另一笔不是今天的本人记账。
2. 进入编辑。期望日期与搜索结果里该笔的日期一致，不是今天。
3. 什么都不改，直接保存。期望它仍在原来的自然日。

## 3. 不该发生的写入

1. 打开样本编辑后直接返回，不保存。期望日期、金额、内容都与打开前一致。
2. 断网或让保存失败（例如提交前断开网络），再恢复后刷新流水。期望失败的那次没有把日期改成今天。
3. 点别人记的账。期望不能进入可保存的编辑，日期不会被改掉。

## 4. 新增没有被带偏

1. 打开「记一笔」。期望日期是今天。
2. 不改日期保存。期望新账在今天。
3. 再记一笔，把日期改成另一天后保存。期望新账在所选那一天。

## 5. 手册

打开 `docs/用户手册.md`，能找到一句说明：小程序编辑自己的记账时，日期一开始就是这笔账原来的日期，不是打开页面的当天。第 10 章里手机网页端的编辑步骤应保持原样。
