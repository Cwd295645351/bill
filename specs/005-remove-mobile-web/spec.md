# Feature Specification: 移除手机端网页

**Feature Branch**: `005-remove-mobile-web`

**Created**: 2026-10-17

**Status**: Draft

**Input**: User description: "移除手机端网页功能"

## Clarifications

### Session 2026-10-17

- Q: 旧的手机网页地址关掉后，要不要留一页说明，告诉用户改去微信小程序或电脑网页？ → A: 不留。直接关停，不提供去向说明，也不跳转到其他入口。
- Q: 有人正停在手机网页上时，要不要按来源拦住他继续调用接口？ → A: 不用。当前没有用户在使用手机网页，不处理页面还开着的情况，也不改公共接口。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 手机浏览器里的记账网页直接关停 (Priority: P1)

家人以前用手机浏览器打开记账网页，登录后可以看账本、看流水、搜索，也可以删除自己记的账、用分享码加入账本，创建者还可以删除账本。新增和编辑早已停用。现在这个网页整个关掉：打开原来的地址不再出现记账产品，也不能改成一页「请改用小程序」之类的说明，更不能跳去电脑网页或小程序。

**Why this priority**: 这是本次要交付的变化。手机网页只剩查看和删除，和微信小程序重复，手册里也已经预告会下线。先关掉入口，才不会再有人误用一个不能补记的旧页面。

**Independent Test**: 在手机浏览器打开原来的记账网页地址，以及从该地址能点进去的账本、流水、搜索、加入账本和个人信息页面。确认都打不开记账功能，也没有替代说明页，并且用这个入口无法登录或改动任何账。

**Acceptance Scenarios**:

1. **Given** 用户知道原来的手机记账网页地址，**When** 在手机或电脑浏览器打开它，**Then** 打不开记账网页，看不到登录框、账本列表、流水、搜索或个人信息，也看不到迁移说明。
2. **Given** 用户收藏了某个账本、某条流水、搜索页或加入账本页面的旧链接，**When** 打开该链接，**Then** 同样打不开对应内容，不展示该账本或该笔流水，也不出现替代说明页。
3. **Given** 用户打开原来的手机记账网页地址，**When** 页面结束加载，**Then** 不会被自动带到电脑网页或微信小程序。

---

### User Story 2 - 已有的账和另外两个入口保持原样 (Priority: P1)

下线只拿掉手机浏览器这个入口。已经记下的账、已经加入的账本、预算、计划和成员关系都还在。电脑网页仍是功能完整的入口；微信小程序仍负责日常补记、查看、修改、删除和邀请家人。记账人、归属人、分享码这些规则不因下线而改变。

**Why this priority**: 下线如果把历史账弄丢，或让电脑、小程序跟着坏掉，家庭账本就无法继续用。保住现有账和剩下的两个入口，与关掉旧网页同样必须同时成立。

**Independent Test**: 下线前记下某个账本的成员、明细笔数和一笔已知明细。下线后用同一账号分别在电脑网页和小程序打开该账本，核对笔数和这笔明细仍在；再在小程序补记一笔、在电脑上查看概览，步骤与下线前一致。整个过程不打开手机网页。

**Acceptance Scenarios**:

1. **Given** 某账本在下线前已有成员和收支明细，**When** 下线完成，**Then** 这些成员和明细仍可通过电脑网页与微信小程序看到，笔数和内容与下线前一致。
2. **Given** 一笔明细是成员甲在任意入口记下的，**When** 甲在电脑网页或小程序中编辑或删除它，**Then** 仍只有甲可以改、可以删，其他成员不行，与下线前的规则相同。
3. **Given** 用户已在电脑注册并在小程序绑定过微信，**When** 下线后打开小程序，**Then** 仍按原方式自动登录，不需要重新注册或重新绑定。
4. **Given** 用户要新建账本、邀请家人、记一笔、查流水、做概览分账、改预算或改计划，**When** 在下线前各自可用的入口上操作，**Then** 电脑网页与小程序能做的事与下线前相同，没有新增也没有减少。
5. **Given** 一名成员当初是在手机网页用分享码加入的，**When** 下线后查看成员名单，**Then** 该成员仍在账本中，不需要重新加入。

---

### User Story 3 - 给人看的说明不再指向手机网页 (Priority: P2)

新来的家人如果按现有使用说明操作，仍可能去打开手机网页。下线后，产品简介、快速开始、登录方式、常见问题和各端能力对照，都不再把手机网页写成可用入口，并写明手机上用微信小程序、完整功能用电脑网页。这里改的是使用说明，不是在已关停的地址上再放一页提示。

**Why this priority**: 入口关掉之后，过时说明会把人带到一个已经不能记账的地址。它依赖故事 1 的下线先成立，但不改变记账规则本身，所以排在后面。

**Independent Test**: 只阅读面向用户的使用说明，按里面的「第一次使用」和「在手机上记账」步骤操作，确认不会被指引去打开手机记账网页，并且能找到小程序和电脑网页两条仍可用的路。

**Acceptance Scenarios**:

1. **Given** 一位未用过本产品的家人阅读使用说明，**When** 按快速开始操作，**Then** 指引是先在电脑网页注册和登录，而不是打开手机记账网页。
2. **Given** 说明中介绍手机上如何记账，**When** 读者查找入口，**Then** 只看到微信小程序，并写明小程序不能注册、需先在电脑注册再绑定。
3. **Given** 读者查看「有哪些客户端」或能力对照，**When** 阅读，**Then** 不再把手机网页列为可以登录、查看、删除或加入账本的一端。
4. **Given** 读者遇到「没有注册入口」「打不开」一类问题，**When** 查看常见问题，**Then** 答案不再建议使用手机网页登录或核对手机网页地址。

---

### Edge Cases

- 用户只收藏了手机网页、手机里没有微信：旧地址直接打不开，不能再在手机上记账，必须自行改用电脑网页。关停页面不负责解释这一点。
- 用户把旧的手机网页地址转发给尚未绑定小程序的家人：对方打开后进不了登录或加入流程，也看不到迁移说明。
- 当前没有人在使用手机网页。已打开但未刷新的旧页面不在本次范围内，不为它拦截公共接口。
- 手机网页上新增、编辑早已不能用：下线后这些页面本身打不开，查看、搜索、删除、加入账本也一并不可用。
- 同一账号在电脑网页和小程序的登录状态不受手机网页下线影响，不需要因此重新登录。
- 不得用跳转到电脑网页、跳转到其他网址，或放一页「请用小程序」来代替关停。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须停止向用户提供手机浏览器中的记账网页，包括登录、账本列表、进入账本、查看流水、搜索筛选、加入账本、删除明细、删除账本和个人信息。
- **FR-002**: 用户打开原来的手机记账网页及其任何子页面时，该入口必须处于关停状态，不得展示账本名称、成员、金额、流水或个人信息。
- **FR-003**: 原手机记账网页地址不得改成去向说明、迁移提示或其他替代页面，也不得自动跳转到电脑网页或微信小程序。
- **FR-004**: 打开原手机记账网页不得再进入登录、查看或改账流程。公共接口保持原样，不按来源拒绝请求。
- **FR-005**: 已有账号、账本、成员关系、收支明细、预算、计划、分享邀请和微信绑定必须原样保留，不得因本次下线删除或要求用户重建。
- **FR-006**: 电脑网页的现有能力与操作方式必须保持不变。
- **FR-007**: 微信小程序的现有能力与操作方式必须保持不变，包括绑定已有账号、自动登录、记账、查看、编辑、删除、邀请和加入。
- **FR-008**: 记账人只能编辑或删除自己录入的明细、归属人规则、分享码有效期，以及「谁可以创建、邀请、删除账本」这些既有权限，必须与下线前一致。
- **FR-009**: 面向用户的使用说明必须去掉「手机网页仍可使用」的表述，并改为：手机上使用微信小程序，完整功能使用电脑网页。该说明不放在已关停的网页地址上。
- **FR-010**: 本次不得新增另一套手机浏览器记账入口来替代被移除的网页。

### Key Entities *(include if feature involves data)*

- **账号**: 用户的登录身份。下线不新建、不注销账号；电脑网页登录和小程序绑定关系保持原样。
- **账本与成员**: 联合记账的隔离单位及其中的人。成员是否仍在账本内，不因当初从哪个入口加入而改变。
- **收支明细**: 账本中的支出和收入。无论当初从哪一端录入，下线后仍属于原账本，仍由原记账人负责修改和删除。
- **手机记账网页**: 手机浏览器中的旧入口。下线后不再提供，不保留说明页，也不再作为可用客户端。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 打开原手机记账网页或其任意旧链接时，100% 看不到登录框、账本列表、流水或迁移说明，也不会被带到电脑网页或微信小程序。
- **SC-002**: 抽查下线前已有的账本，下线后在电脑网页和小程序中看到的成员与明细笔数与下线前一致，抽查范围内丢失笔数为 0。
- **SC-003**: 已会使用本产品的成员，仍能在小程序完成一笔日常记账，并在电脑网页完成一次概览查询；完成这两件事的步骤与下线前相同。
- **SC-004**: 打开原手机记账网页时，100% 看不到登录框、账本内容或可提交的改账操作。公共接口的行为与下线前一致。
- **SC-005**: 按更新后的使用说明走完「第一次使用」和「在手机上记账」，操作步骤中不再出现打开手机记账网页；新用户能据此找到电脑网页和微信小程序。

## Assumptions

- 「手机端网页」指用户手册第 10 章所说的、在手机浏览器中打开的记账网页，不是微信小程序。小程序继续作为手机上的记账入口。
- 旧地址直接关停。不保留去向说明，不自动跳转到电脑网页或小程序。用户要知道改去哪里，只能通过更新后的使用说明，而不是通过旧地址本身。
- 不使用微信的用户，下线后不能在手机上记账，需改用电脑网页。这是关掉手机网页的直接结果，不另做手机浏览器替代品。
- 电脑网页与微信小程序的功能范围本次不扩大、不缩小。日常补记以小程序或电脑为准；统计、分账、预算、计划和类型配置仍只在电脑上操作。
- 手册已经预告手机网页会下线，且新增、编辑已停用。本次是兑现该预告，并把剩余的查看、删除和加入一并移除。
- 项目宪章 2.0.0 已去掉手机网页。`/mobile/` 直接关停，不留说明页，不跳转。本规格按该宪章安排下线。
- 当前没有用户在使用手机网页。不处理「页面还开着继续提交」，也不为此修改公共接口。
- 历史账务数据不迁移、不清洗。部署和工程上如何撤下旧网页，留到规划阶段决定。
