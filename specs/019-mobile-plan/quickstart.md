# Quickstart: 019-mobile-plan

## 前提

- 后端可访问；至少有一个测试账本，可准备「有计划 / 无计划」两种状态。
- mobile-h5 可打开 `/mobile/`；微信开发者工具打开 `miniapp/`（已构建 npm）。
- 接口摘要见 [contracts/plan-api.md](./contracts/plan-api.md)；模型见 [data-model.md](./data-model.md)。
- 可选：同一账本在 PC 计划页可对照标题、内容、优先级与同档顺序。

## 1. 按优先级查看（P1 / SC-001）

**小程序与 H5 各做一遍。**

1. 登录 → 进入测试账本。
2. 确认账本内底栏五入口可见；从「记账」或「预算」切换到「计划」。
3. 有数据时期望：标题「计划」；顶栏说明「不会自动变成记账」；固定高 / 中 / 低三档；卡片显示标题与内容；同档顺序与 PC 一致。
4. 无数据时期望：三档仍在，每档为空态（如「这一档还没有」），仍有「新增计划」。
5. 点「概览」「资产」：
   - **小程序**：进入未交付占位页并提示到电脑端；入口不置灰不消失。
   - **H5**：停留当前页，toast「请到电脑端查看或管理」；入口不置灰不消失。

耗时目标：有数据账本，正常网络下约 30 秒内看清某条计划所属档与内容。

## 2. 新增 → 编辑 → 删除（P1 / SC-002）

**两端各完整走通。**

1. 新增：打开表单，确认默认优先级为**高**；填标题与内容 → 保存 → 卡片出现在高优先级档。
2. 负例：标题或内容为空（或仅空格）→ 不保存并提示；不因「字数过长」被移动端单独拒收。
3. 编辑：改标题 / 内容 / 优先级（例如改为中）→ 保存后出现在对应档，原档若空则显示档内空态。
4. 删除：确认后条目消失；取消确认则仍在；该账本既有记账明细不变。

## 3. 多端一致（P2 / SC-003）

1. PC 为账本新增 / 修改一条计划。
2. 小程序与 H5 打开计划页：标题、内容、优先级分区及同档相对顺序与 PC 一致。
3. 在 H5（或小程序）改优先级或删除 → 另一移动端与 PC 刷新后一致。

## 4. 校验与边界（SC-004）

1. 未填标题或内容点保存：100% 失败且有提示。
2. 删除弹窗点取消：计划仍在列表中。
3. 某一档无计划、其它档有计划：空档显示档内空态，其它档正常，不得整页伪装成「完全没有计划」而藏起其它档。
