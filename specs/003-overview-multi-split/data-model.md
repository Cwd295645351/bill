# Data Model: 概览多人分账

分账不新增表，也不改已有列。规则与 [spec.md](./spec.md) 一致，接口形状见 [contracts/overview-settlement.md](./contracts/overview-settlement.md)。

## 账本成员（已有，不改）

表 `bill_users`。结算读取当前账本未删除关系中的成员。本表没有创建时间。

| 字段 | 本次用法 |
|------|----------|
| id | 分摊顺序和转账匹配顺序的依据，升序。不改账本详情里成员数组的顺序 |
| bill_id | 只计算这个账本 |
| user_id | 与记账上的记账人、归属人对照 |
| user_name | 文案和支出结构标题用这个姓名 |

已经不在这张表里、但区间支出上仍写着的记账人或归属人，不加入成员名单，只作为结算中的局外人。

## 概览规则（已有，不改）

表 `bill_overview_rules`。只使用 `enabled` 为真的规则。

| 规则 | 结算时 |
|------|--------|
| `quantity` | 浏览器提交该规则的数量和一名当前成员。扣减 = 数量 × 账本中的 `unit_price`，四舍五入到分。未提交的启用数量规则按数量 0。单价不采用浏览器传来的值 |
| `cost_type` | 从该成员的有效收入中减去「归属人就是该成员、支出类型等于 `cost_type_id`」的支出合计。不减去公共支出分到他头上的部分 |

停用的规则即使被提交也不生效。

## 记账明细（已有，不改）

表 `transactions`。结算只读，不写。

| 字段 | 本次用法 |
|------|----------|
| id | 公共支出分给每人的份额要能对回这一笔，供下钻使用 |
| bill_id | 账本隔离 |
| date | 落入查询区间才参与。区间口径与现有概览汇总相同 |
| type | `1` 支出参与垫付和承担；`2` 收入只参与有效收入。其它值忽略 |
| money | 记账金额，先换成整数分。报销进度不减少它 |
| reimbursement | 不作为过滤条件，也不改变金额 |
| user_id | 记账人，视为垫付了这笔支出 |
| belong_user_id | 空或未填视为「全部」。否则是归属人 |
| belong_user_name | 局外人在转账文案里用这个姓名 |
| cost_type_id / cost_type_name | 支出结构按类型汇总。支出类型「基金」（`1015`）照常进入分账 |
| is_del | 为真的不参与 |

收入且归属为「全部」的，不计入任何成员的有效收入。

## 计算对象（不落库）

这些只存在于一次查询的结果里。

### 成员结算

每个当前成员一条，顺序为 `bill_users.id` 升序。

| 项 | 含义 |
|----|------|
| 有效收入 | 归属到本人的收入 − 规则扣减。可以为负 |
| 权重 | 有效收入小于 0 时为 0，否则等于有效收入。全体都是 0 时，本次查询改为每人权重 1 |
| 垫付 | 作为记账人的支出合计 |
| 承担 | 归属本人的支出 + 分到的公共支出 |
| 净额 | 垫付 − 承担。正数表示应收，负数表示应付 |

局外人只有垫付、承担和净额，没有有效收入和权重，也不出现在个人支出结构里。

### 公共支出合计的份额

仅归属为「全部」的支出。先加总，再按 [research.md](./research.md) 第 4 节只分一次。各人份额之和等于公共支出总额，每人份额不小于 0。结算响应不包含逐笔份额。个人支出结构按类型使用与这次合计一致的金额。

### 转账建议

付款人、收款人、金额（分）。产生规则见 [research.md](./research.md) 第 5 节。参与者包含净额不为 0 的当前成员和局外人。

### 支出结构

- 「全部」：区间内全部支出按支出类型加总，不按人拆。
- 每个当前成员：归属本人的支出按类型加总，再加上本人分到的公共支出按类型加总。不含归属其他人的支出。

一名当前成员时，结果里不带个人支出结构。

## 状态

没有新的持久状态。改了日期或数量但未再次查询时，电脑端继续显示上一次成功的结算，不在输入时重算。

## 校验

- 查询人必须是该账本的当前成员。
- 数量必须是大于等于 0 的数。负数拒绝。缺省当 0。
- 数量规则的归属人必须是当前成员。
- 规则 id 必须属于该账本且为已启用的数量规则。其它 id 拒绝，不静默忽略。
