# Quickstart: PC 端新增记账支持附图

**Branch**: `020-pc-add-record-images` | **Date**: 2026-11-10

手工验收指南。契约见 [contracts/pc-add-images.md](./contracts/pc-add-images.md)；数据规则见 [data-model.md](./data-model.md)。

## 前置条件

1. 本地已启动 API（`server/`）与 PC 前端（`frontend/`，`/pc/`）。
2. 准备至少两个同账本账号（记账人 A、成员 B），以及另一账本账号 C（可选，用于隔离回归）。
3. 准备若干 jpeg/png 小图，以及一张 >10MB 或非图片文件用于失败用例。

## 启动（示例）

```bash
# 终端 1：API
cd server && pnpm run dev

# 终端 2：PC
cd frontend && pnpm run dev
```

按本机既有方式登录并进入某一账本「记账」页。

## 主路径验收

### V1 — 单条新增附图（支出）

1. 以 A 登录，点「新增」。
2. 填写日期、支出类型、金额、归属人等必填项。
3. 在照片区选择 1～3 张合格图片；可再单张删掉其中一张。
4. 点「保存」。
5. **期望**：成功提示；时间线该笔出现「查看照片」；张数与顺序与保存前一致。

### V2 — 收入 + 切换收支保留照片

1. 新增表单选 2 张照片（支出态）。
2. 切到「收入」，确认照片仍在；补全收入必填项后保存。
3. **期望**：保存为收入明细且带这 2 张照片。

### V3 — 不附图与取消（无脏数据）

1. 新增不选照片并保存 → 行为与改前一致，无照片。
2. 另开新增，选图后点「取消」→ 不产生记账；流水无新照片入口；选图阶段网络面板中**不应**出现 `POST /transaction/image`。
3. 编辑一笔账，新选照片后点「取消」→ 原照片不变；网络面板中**不应**出现本次新文件的上传请求。

### V4 — 失败与上限

1. 选非图片或 >10MB → 选图时即拒绝该张（本地校验），已填字段与其它合格图保留；此时无上传请求。
2. 已满 9 张再加 → 「最多 9 张」。
3. 点保存后断网 / 上传失败 → 无「缺图新账」；表单内容与本地已选合格图仍在。

### V5 — 权限与跨端

1. 成员 B 打开同账本 → 能看 A 新增的照片，不能编辑该笔。
2. （可选）小程序或 H5 打开同笔 → 张数顺序一致。
3. （可选）账号 C 的其它账本 → 看不到该笔与照片。

### V6 — 编辑上传时机、删整笔与文案

1. A 编辑刚新增的带图账，删一张再补一张并保存 → 保存时才出现新文件上传，其后编辑成功；各端一致。
2. A 删除该整笔带图账并确认 → 同账本成员不可再打开这些照片。
3. 检查新增/编辑界面 tip：**无**「新记一笔不能附照片」。
4. 检查 `docs/用户手册.md` 电脑端 6.5/6.6：**有**单条新增可附图说明，**无**旧限制句。

### V7 — 批量解析与统计/导出回归

1. 支出态「批量解析」写入 ≥3 条并保存 → 明细无照片；金额/日期/类型与核对结果一致。
2. 对带图账抽查概览合计与账本身金额一致；导出明细文件无照片列。
