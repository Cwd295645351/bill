# Feature Specification: PC 路由 History 与鉴权回跳

**Feature Branch**: `013-pc-router-history`

**Created**: 2026-11-04

**Status**: Draft

**Input**: User description: "PC 端路由六项一并改：重写守卫、登录 redirect、401/logout 统一带 fullPath、账本进 URL、catch-all 404、预算→记账用 query；另将 Hash 改为 History。不改已归档 specs/001–012。"

## Background

电脑网页端当前用 Hash 地址（`#/layout/...`），登录守卫形同虚设，登出与过期后无法回到原页，账本上下文主要靠 sessionStorage，预算跳记账靠隐性状态，未知路径无落地页。用户希望一次收齐鉴权、回跳、账本 URL、404、跨页筛选与 History 模式，便于刷新、分享与部署深链。

## User Scenarios & Testing *(mandatory)*

范围：PC 网页端。微信小程序与移动端 H5 路由不在本需求内修改。

### User Story 1 - 未登录被拦住并可回到原页 (Priority: P1)

未登录访问需登录的页面时，进入登录页并记住原目标；登录成功后回到该页（目标必须是站内相对路径）。无有效回跳时进入账本列表。

**Why this priority**: 鉴权与回跳是安全与体验的基础。

**Independent Test**: 清空登录态后打开某个账本内页地址，应落到登录页；登录后回到该账本内页。

**Acceptance Scenarios**:

1. **Given** 未登录，**When** 打开需登录的账本内页地址，**Then** 进入登录页且地址中带有可识别的回跳信息。
2. **Given** 登录页带有安全的站内回跳，**When** 登录成功，**Then** 进入该回跳目标页。
3. **Given** 回跳缺失或不安全（站外或协议相对等），**When** 登录成功，**Then** 进入账本列表页。

---

### User Story 2 - 账本上下文出现在地址栏且可刷新恢复 (Priority: P1)

进入某个账本后，地址中可见账本标识与当前页签（记账/概览/预算/计划/资产）。刷新页面后仍停留在同一账本同一页签。顶栏切换页签会更新地址。

**Why this priority**: 解决刷新丢上下文与不可分享深链的核心问题。

**Independent Test**: 进入账本切到「资产」后复制地址，新会话登录后打开该地址应进入同一账本资产页。

**Acceptance Scenarios**:

1. **Given** 已登录且在账本列表，**When** 点开某账本，**Then** 地址变为含该账本标识与默认页签（记账）的路径。
2. **Given** 已在某账本内，**When** 顶栏切换页签，**Then** 地址中的页签段同步变化且页面内容对应。
3. **Given** 已打开某账本某页签地址，**When** 刷新浏览器，**Then** 仍显示同一账本同一页签（登录态有效时）。

---

### User Story 3 - 过期或退出后仍可回跳 (Priority: P1)

接口认证失败被迫退出，或用户主动退出时，进入登录页并尽量带上退出前所在页；再次登录后可回到该页（安全校验同 US1）。

**Why this priority**: 与守卫口径统一，避免「盯着某页操作却被踢回列表」。

**Independent Test**: 在账本内页制造需重新登录的情况（或点退出），登录页应带原页回跳；登录后回到原页。

**Acceptance Scenarios**:

1. **Given** 用户在账本内页，**When** 因认证失败被退出登录，**Then** 登录页带有该内页的安全回跳。
2. **Given** 用户在账本内页点退出登录，**When** 到达登录页，**Then** 同样带有安全回跳（或产品选择不带时在假设中说明；默认带）。

---

### User Story 4 - 未知路径有简单 404 (Priority: P2)

访问不存在的 PC 路径时，看到简单的「页面不存在」说明，并可回到账本列表或登录（按是否已登录）。

**Why this priority**: 兜底体验，避免白屏或错落到登录无提示。

**Independent Test**: 登录后打开明显不存在的路径，应看到 404 页而非空白。

**Acceptance Scenarios**:

1. **Given** 已登录，**When** 打开不存在的路径，**Then** 显示简单 404 页并提供回到账本列表的入口。
2. **Given** 未登录，**When** 打开不存在的需登录路径，**Then** 可先被引导登录；登录后落到 404 或列表（实现可选其一，须在假设中固定）。

---

### User Story 5 - 预算跳到记账时筛选出现在地址里 (Priority: P2)

从预算点击某类型跳到记账时，目标地址带上该支出类型筛选；刷新后筛选仍在。仍兼容旧的会话内传递方式作为回退。

**Why this priority**: 跨页状态可刷新、可分享。

**Independent Test**: 预算页点某类型进入记账，地址含类型参数；刷新后列表仍按该类型筛选。

**Acceptance Scenarios**:

1. **Given** 预算页某类型有数据，**When** 点击跳转记账，**Then** 记账页地址含该类型筛选参数且列表按该类型过滤。
2. **Given** 带类型参数的记账地址，**When** 刷新，**Then** 筛选条件仍生效。

---

### User Story 6 - 地址不再依赖 Hash，深链可刷新 (Priority: P1)

PC 使用 History 路径（无 `#`）。开发与生产在刷新深链时仍打开前端应用而非服务器 404。旧 `#/...` 书签尽量自动转到对应 History 路径；若环境限制无法自动转，手册说明新地址形态。

**Why this priority**: 用户明确要求 Hash→History，且与账本深链绑定。

**Independent Test**: 打开无 `#` 的账本内页并刷新，页面仍可用；旧 `#/layout/bill` 类地址尽可能被带到新路径。

**Acceptance Scenarios**:

1. **Given** 开发环境已启动 PC，**When** 直接打开/刷新无 `#` 的账本内页路径，**Then** 应用正常显示而非开发服务器 404。
2. **Given** 生产静态托管按部署说明配置，**When** 刷新无 `#` 的 PC 深链，**Then** 返回前端入口而非裸 404。
3. **Given** 用户仍打开旧的 `#/…` 地址，**When** 页面加载，**Then** 尽可能替换为对应无 `#` 路径；无法覆盖的情形在手册中说明。

---

### Edge Cases

- 回跳参数指向站外、`//evil`、带 `://` 时一律忽略，改去账本列表。
- 账本 ID 在地址中但用户无权限：沿用现有接口错误提示，不在本需求新造权限页（除非已有）。
- 仅有账本列表、地址无账本 ID 时，顶栏只显示「账本」。
- 旧路径 `/layout/record` 等无账本段时：若会话中仍有账本 ID，重定向到新形态；否则回账本列表。
- History 模式下静态资源 `base` 须与部署前缀（如 `/pc/`）一致，避免嵌套路径下脚本 404。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: PC 路由守卫须按「是否登录」拦截；公开页（至少登录页）可匿名访问；未登录访问受保护页须进入登录并携带安全回跳。
- **FR-002**: 登录成功须优先进入安全的回跳目标；否则进入账本列表。
- **FR-003**: 主动退出与认证失败退出进入登录页时，须尽可能携带退出前页面的安全回跳，与守卫口径一致。
- **FR-004**: 进入账本后的业务页地址必须包含账本标识与页签；顶栏切页签与进入账本须更新地址；刷新后在登录有效时可恢复。
- **FR-005**: 未知 PC 路径须展示简单 404 页（已登录时可回账本列表）。
- **FR-006**: 预算跳转记账须通过地址查询参数传递支出类型筛选；记账页读取该参数并应用筛选；可保留旧会话传递作兼容。
- **FR-007**: PC 须使用 History 模式（地址无 `#` 路由）；开发与生产文档/配置须支持深链刷新。
- **FR-008**: 须尽量兼容旧 Hash 书签到新路径；不能自动兼容的部分写入用户手册。
- **FR-009**: 不得修改 `specs/` 下已归档目录（001–012）既有正文；本能力仅落在本目录。
- **FR-010**: 不得为完成本需求而引入与需求无关的根 `package.json` / `.gitignore` 噪声改动。

### Key Entities

- **安全回跳目标**: 站内相对路径字符串，须通过安全校验。
- **账本页地址**: 含账本标识与页签名的路径。
- **记账筛选参数**: 地址查询中的支出类型标识。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 未登录访问受保护深链时，100% 进入登录页而非业务页内容。
- **SC-002**: 带安全回跳的登录成功后，用户落到原目标页（抽样 3 条深链均通过）。
- **SC-003**: 账本内切换 5 个页签时，地址栏页签段与页面一致；刷新后仍一致。
- **SC-004**: 预算跳记账后，地址含类型参数且刷新后筛选仍在。
- **SC-005**: 未知路径展示 404 而非空白。
- **SC-006**: 代码审查无对归档 specs（001–012）正文的修改；无无关 package.json/.gitignore 污染。

## Assumptions

- 账本内 URL 形态采用「账本列表仍为列表路径；进入账本后为列表路径下的账本标识 + 页签」；默认进入页签为记账。
- 退出登录默认携带当前页作为回跳（登录页自身除外）。
- 未登录撞上未知路径：先按受保护页处理（去登录并带 redirect），登录后再进 404。
- 生产 PC 仍挂在既有 `/pc/` 前缀下；History 的资源 base 与之对齐。
- 小程序与 mobile-h5 本需求不改路由。

## Out of Scope

- 重做权限模型或新增独立「无权限」业务页（超出简单 404）。
- 修改后端认证协议。
- 修订归档 specs（001–012）正文。
- 为 History 之外的端统一路由库。
